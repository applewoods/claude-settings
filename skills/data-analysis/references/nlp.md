# 텍스트·LLM 평가

언제 읽나: 텍스트 분류·생성·정보 추출 모델을 평가할 때, LLM을 평가자로 쓸 때, 사전학습 모델로 벤치마크 결과를 낼 때.

## 1. 분할과 중복
- 정확 중복 + 근접 중복(정규화 후 해시, MinHash 등)을 train/test 간에 확인하고 개수를 보고한다.
- 같은 저자·문서·대화·제품에서 나온 문장은 그룹 분할(문장 단위로 섞으면 누수).
- 시간이 의미 있는 데이터(뉴스, SNS)는 시간순 분할도 고려한다.

## 2. 데이터 오염(contamination)
- 사전학습 모델(특히 LLM)이 평가 데이터를 학습 중에 봤을 수 있다. 공개 벤치마크 점수는 오염으로 부풀 수 있다.
- 점검 방법(완벽한 것은 없다): 학습 말뭉치가 공개되면 n-gram 중복 검사, 벤치마크 문항의 앞부분을 주고 뒷부분을 그대로 생성하는지(암기) 확인, 모델 학습 종료 이후에 만든 데이터로 추가 평가, 문항을 바꿔 쓴(perturbed) 버전과의 성능 차.
- 보고: 모델의 학습 데이터 기준일(알려진 경우), 오염 점검 방법과 결과, 확인 불가면 한계로 명시.

## 3. 지표의 한계
- **BLEU·ROUGE·METEOR**: n-gram 겹침 → 의미가 같아도 표현이 다르면 낮고, 사실 오류가 있어도 높을 수 있다. 사람 판단과의 상관이 과제·시스템 수준에 따라 약하다. 단독으로 품질을 주장하지 않는다.
- BLEU는 토크나이저·설정에 따라 값이 달라진다 → `sacreBLEU`로 계산하고 서명(signature)을 보고한다(Post 2018).
- BERTScore·COMET 같은 학습된 지표: 더 나은 상관을 보이는 경우가 많지만 기반 모델·버전에 따라 값이 다르다 → 모델 이름·버전 보고.
- 분류: 클래스 불균형이면 macro-F1과 클래스별 지표.
- 생성 과제는 **과제 지표**(정답 일치, 실행 성공률, 사실성 검사)와 **사람 평가**를 병행한다. 사람 평가는 평가자 수, 지침, 평가자 간 일치도(Krippendorff's α, Cohen's κ), 블라인드·순서 무작위화를 보고한다.

## 4. LLM을 평가자로 쓸 때(LLM-as-judge)
- 알려진 편향: **위치 편향**(먼저/나중 제시된 답 선호), **길이(장황함) 편향**, **자기 선호**(같은 계열 모델 출력 선호)(Zheng et al. 2023).
- 통제: 쌍 비교는 순서를 바꿔 두 번 평가하고 불일치를 보고, 평가자 모델과 평가 대상 모델 계열을 분리, 길이 통제 분석, 사람 평가 부분 표본과의 일치도 보고.
- 평가 프롬프트·평가자 모델 이름·버전·온도·날짜를 기록한다(API 모델은 조용히 바뀔 수 있다).

## 5. 프롬프트·디코딩 민감도
- LLM 결과는 프롬프트 표현·예시 순서·형식에 따라 크게 달라질 수 있다. 여러 프롬프트 변형의 평균과 범위를 보고하거나, 프롬프트를 개발 세트에서만 고르고 test에는 1회 적용한다.
- 디코딩 설정(온도, top-p, 최대 길이, 시드)을 보고한다. 온도 > 0이면 여러 번 샘플링해 분산을 보고한다.
- test 세트를 보며 프롬프트를 고치면 튜닝 누수다.

## 6. 유의성
- 같은 test 세트에서 두 시스템 비교: 쌍체 부트스트랩 또는 근사 무작위화(`model-comparison.md`). 문장 수준 점수가 없는 지표(코퍼스 BLEU)도 부트스트랩으로 가능.
- 여러 데이터셋·여러 언어에서 비교하면 다중 비교 보정.

## 7. 베이스라인
- 하한: 다수 클래스, 키워드·TF-IDF + 로지스틱 회귀(텍스트 분류에서 의외로 강하다).
- 강한 베이스라인: 같은 크기·같은 데이터로 미세조정한 표준 사전학습 모델, 같은 조건의 zero/few-shot LLM.
