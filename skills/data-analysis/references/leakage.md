# 데이터 누수 유형과 점검

언제 읽나: 분할·전처리·특성 생성 파이프라인을 짤 때, 결과가 기대·선행연구보다 훨씬 좋을 때, 남의 코드를 검토할 때.
분류 틀은 Kapoor & Narayanan(2023, *Patterns*)의 ML 기반 과학 누수 분류를 참고했다.

## 유형별 점검표
| 유형 | 예 | 막는 법 |
|---|---|---|
| **전처리 fit 누수** | 전체 데이터로 스케일러·PCA·결측 대체·인코더 fit 후 분할 | 분할 먼저. CV에서는 `Pipeline`/`ColumnTransformer`를 `cross_val_score`에 통째로 넣는다 |
| **특성 선택 누수** | 전체 데이터에서 타깃과 상관 높은 특성을 고른 뒤 CV | 특성 선택도 파이프라인 안(fold마다). 무작위 데이터로도 높은 점수가 나오는 고전적 함정 |
| **오버샘플링 누수** | 분할 전 SMOTE → 합성 샘플이 test 이웃이 됨 | 학습 fold 안에서만(`imblearn` 파이프라인) |
| **타깃 누수** | 예측 시점 이후에만 알 수 있는 변수(퇴원 코드, 사후 검사), 라벨에서 파생된 변수 | 각 특성에 "예측 시점에 이 값을 알 수 있나?"를 표로 점검 |
| **그룹(정체성) 누수** | 같은 피험자·기기·환자·문서 출처가 train/test 양쪽에 | 그룹 분할. 모델이 사람을 알아보는 것인지 과제를 푸는 것인지 구분 |
| **시간 누수** | 시계열 무작위 분할, 미래 데이터로 만든 정규화 통계·이동평균(중심 윈도우) | 시간순 분할, 통계는 과거 구간으로만, 인과(후행) 윈도우만 |
| **윈도우 겹침 누수** | 50% 겹치는 슬라이딩 윈도우를 만든 뒤 무작위 분할 → 이웃 윈도우가 양쪽에 | 분할을 먼저 하고 윈도잉. 경계에 윈도우 길이 이상 gap(purge) |
| **중복 누수** | 동일·거의 동일 행·문서·이미지가 양쪽에 | 분할 전 중복 제거 또는 중복 묶음을 그룹으로 |
| **튜닝 누수** | test 점수로 하이퍼파라미터·임계값·epoch·특성 집합 선택, test를 여러 번 보고 고침 | test는 1회. 여러 번 봤다면 그 사실을 보고 |
| **사전학습·벤치마크 오염** | 평가 데이터가 사전학습 말뭉치·이미지넷 등에 포함 | `nlp.md`의 오염 점검. 공개 이후 수집한 데이터로 추가 평가 |
| **라벨링 누수** | 라벨러가 모델 출력이나 다른 split 정보를 보고 라벨링 | 라벨링 절차 문서화 |
| **분포 누수(표본 구성)** | 클래스별로 다른 장비·병원·시기에서 수집 → 모델이 장비를 학습 | 수집 출처를 변수로 기록하고 출처별 성능·출처 분할 확인 |

## 빠르게 의심하는 신호
- 선행연구보다 크게 좋다, 거의 완벽하다(AUC 0.99).
- 단순 모델이 복잡한 모델만큼 좋다(누수된 특성 하나가 답을 알려 줌).
- 특성 중요도 1위가 ID·타임스탬프·파일 경로·수집 순서·행 번호 같은 변수.
- 그룹 분할로 바꾸면 성능이 크게 떨어진다 → 원래 결과는 그룹 누수였다.
- 무작위로 섞은 라벨로 학습해도 우연 수준 이상 → 파이프라인 버그·누수(`permutation_test_score`로 확인 가능).

## 점검 절차 (verifier가 따라 할 수 있게)
1. 분할 코드가 전처리·특성 생성·리샘플링보다 먼저 실행되는지 줄 번호로 확인.
2. `fit`/`fit_transform` 호출을 모두 찾아 입력이 train 부분인지 확인.
3. train/test의 그룹 ID 교집합이 비어 있는지 출력(`set(g_tr) & set(g_te)`).
4. 시계열: train 최대 시각 < test 최소 시각인지, 그 사이 gap이 윈도우 길이 이상인지 출력.
5. 중복: 해시(텍스트는 정규화 후)로 train-test 교집합 수를 출력.
6. 특성 목록에 대해 "예측 시점에 알 수 있나" 표를 만든다.
