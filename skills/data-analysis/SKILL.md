# 데이터 분석 매뉴얼

## 환경과 코드
- 환경은 conda. 새 패키지가 필요하면 설치 명령(`conda install` 또는 `pip install`)을 먼저 보여 주고 묻는다.
- 코드는 스크립트(.py)로 작성한다. 노트북은 내가 요청할 때만.
- **코드는 단순하게.** 요청한 분석에 필요한 만큼만 쓴다. 불필요한 클래스·추상화·범용화는 하지 않는다.
- 하이퍼파라미터·경로·옵션은 설정 파일(yaml 등)로 분리한다.

## 재현성
- random / numpy / torch 시드를 항상 고정한다.
- 실행마다 설정과 결과를 기록한다(예: `results/<날짜_실험명>/`에 config, 지표, 로그 저장).
- **원본 데이터(raw)는 절대 수정하지 않는다.** 가공 결과는 별도 폴더·파일로 저장한다.

## 전처리: 말없이 바꾸지 않는다
- 결측치·이상치를 제거하거나 바꾸기 전에 몇 건인지, 어떻게 처리할지 먼저 알린다. 판단이 갈리면 묻는다.
- 행·열을 걸러내면 전후 개수를 보고한다.

## 데이터 누수 방지
- 데이터 분할을 가장 먼저 한다. 스케일링·인코딩·결측치 대체·특성 선택은 학습 데이터에만 fit하고 검증·테스트에는 transform만 한다.
- **시계열·센서 데이터는 시간 순서로 분할한다.** 무작위 분할·셔플을 하지 않는다. 같은 대상(사람·기기)이 학습과 테스트에 섞이지 않게 그룹 분할을 검토한다.
- 테스트 세트는 최종 평가에만 한 번 쓴다. 튜닝은 검증 세트나 교차검증으로 한다.
- 텍스트 데이터는 중복·유사 문서가 학습과 테스트에 나뉘어 들어가지 않았는지 확인한다.

## 실행하고 보고한다
- **실행하지 않은 결과를 보고하지 않는다.** 수치·그래프는 실제로 돌린 출력만 쓴다.
- 실행하지 못했으면(시간, GPU, 데이터 없음) 그렇다고 말하고, 예상치는 예상치라고 표시한다.
- 오래 걸리는 학습은 작은 샘플로 먼저 돌려서 코드가 끝까지 도는지 확인한 뒤 전체를 실행한다.

## 결과 보고
기본 형태는 다음 세 가지다.
1. **요약 문단**: 핵심 결과를 몇 줄로
2. **표**: CSV로 저장하고 대화에는 마크다운 표로
3. **논문용 그림**: PDF(벡터)와 PNG(300dpi)로 저장. 축 이름·단위·범례를 넣고, 색만으로 구분하지 않는다(선 모양·마커 병행).

반드시 포함할 것:
- **통계**: p-value만 쓰지 않는다. 효과 크기와 95% 신뢰구간을 함께 쓴다.
- **ML/DL**: 여러 시드(기본 5개) 결과의 평균 ± 표준편차
- **베이스라인 비교**: 단순 모델(평균 예측, 로지스틱 회귀 등)과 비교
- **가정과 한계**: 검정의 가정을 확인했는지, 데이터의 한계는 무엇인지

## 완료 기준
마치기 전에 스스로 확인한다.
- [ ] 코드가 처음부터 끝까지 실제로 실행됐고, 보고한 수치는 그 출력과 일치한다.
- [ ] 분할 방식과 전처리 순서에 누수가 없다(시계열은 시간 순 분할).
- [ ] 전처리로 바뀐 내용(제거·대체 건수)을 보고했다.
- [ ] 시드가 고정됐고, 설정과 결과가 기록됐다. 원본 데이터는 그대로다.
- [ ] 효과 크기·신뢰구간 또는 평균±편차, 베이스라인 비교, 한계가 들어 있다.
