# 데이터 분석 매뉴얼

> **팀으로 진행:** 여러 단계이거나 검증이 중요한 일은 `team-orchestration` 스킬의 "데이터 분석" 팀 구성(scout·builder·expert·verifier)으로 나눠 맡긴다. 각 팀원은 이 매뉴얼을 따른다. 분석 설계(검정·모형 선택, 평가 설계)는 expert가 정한다.

이 매뉴얼의 기준: **방법론 심사위원이 "이 결론이 이 설계와 이 숫자로 정당화되는가"를 물었을 때 답할 수 있어야 한다.** 깔끔하게 돌린 잘못된 분석이 가장 위험하다.

## 환경과 코드
- 환경은 conda. 새 패키지가 필요하면 설치 명령(`conda install` 또는 `pip install`)을 먼저 보여 주고 묻는다.
- 코드는 스크립트(.py)로 작성한다. 노트북은 내가 요청할 때만.
- **코드는 단순하게.** 요청한 분석에 필요한 만큼만 쓴다. 불필요한 클래스·추상화·범용화는 하지 않는다.
- 하이퍼파라미터·경로·옵션은 설정 파일(yaml 등)로 분리한다.

## 재현성
- random / numpy / torch 시드를 항상 고정한다(`templates/seed.py`). GPU 결과는 시드를 고정해도 완전히 같지 않을 수 있음을 안다.
- 실행마다 설정·결과·코드 버전·환경을 기록한다(`results/<날짜_실험명>/`, `templates/run_logger.py`).
- **원본 데이터(raw)는 절대 수정하지 않는다.** 가공 결과는 별도 폴더·파일로 저장한다.

## 1. 분석 전에 정한다 (설계)
코드를 쓰기 전에 아래를 적어 두고, 판단이 갈리면 묻는다. 나중에 바꾸면 바꿨다고 기록한다.
- **연구 질문의 종류**: 차이·연관·예측·인과 중 무엇인가. 인과 주장은 무작위 배정이나 식별 전략이 있을 때만 한다(관찰 데이터의 회귀 계수 = 연관).
- **분석 단위와 독립성**: 무엇이 독립 관측인가(사람·기기·문서·세션). 한 사람의 여러 측정·윈도우·문장은 독립이 아니다 → 피험자 단위 집계, 혼합효과 모형, 그룹 분할 중 하나로 처리한다. **이걸 놓친 의사반복(pseudoreplication)이 가장 흔한 심사 지적이다.**
- **주 지표·주 가설은 하나(또는 소수)로 미리 정한다.** 나머지는 보조·탐색 분석으로 표시한다.
- **일반화 대상**: 새 시점? 새 사람? 새 기기? 이것이 분할 방식을 정한다(아래 2).
- **표본 크기**: 확증 연구면 사전 검정력 분석으로 정하고, 이미 정해진 데이터면 탐지 가능한 최소 효과(MDE)를 적는다. 사후 검정력(observed power)은 계산하지 않는다.

## 2. 분할과 누수 방지
- 데이터 분할을 가장 먼저 한다. 스케일링·인코딩·결측치 대체·특성 선택·오버샘플링은 학습 데이터에만 fit하고 검증·테스트에는 transform만 한다. CV에서는 `Pipeline`으로 fold마다 다시 fit한다.
- **시계열·센서 데이터는 시간 순서로 분할한다.** 무작위 분할·셔플을 하지 않는다. 윈도우가 겹치면 분할 경계에 간격(gap)을 둔다.
- **같은 대상(사람·기기·문서 출처)이 학습과 테스트에 섞이지 않게 그룹 분할한다.** 새 대상으로 일반화를 주장하면 필수이고, 아니면 왜 아닌지 적는다.
- 테스트 세트는 최종 평가에만 한 번 쓴다. 튜닝·모델 선택·임계값·조기 종료는 검증 세트나 (중첩) 교차검증으로 한다.
- 텍스트 데이터는 중복·유사 문서가 학습과 테스트에 나뉘어 들어가지 않았는지, 사전학습 모델이 평가 데이터를 봤을 가능성(오염)이 있는지 확인한다.
- 타깃 누수(예측 시점에 알 수 없는 변수, 라벨에서 파생된 변수)를 변수 목록으로 점검한다. 세부 유형은 `references/leakage.md`.
- **결과가 기대보다 훨씬 좋으면 누수부터 의심한다.**
- 누수 점검으로 두 분할(예: 무작위 vs 그룹·시간 분할)을 비교했으면 차이가 작아도 두 값을 나란히 수치로 보고한다. "차이 없음"도 근거와 함께 남겨야 할 결과다(다른 데이터에서는 차이가 날 수 있으므로 분할 방식 선택의 근거가 된다).

## 3. 전처리: 말없이 바꾸지 않는다
- 결측치·이상치를 제거하거나 바꾸기 전에 몇 건인지, 어떻게 처리할지 먼저 알린다. 판단이 갈리면 묻는다.
- 행·열을 걸러내면 전후 개수를 보고한다(가능하면 그룹·클래스별로도).
- 결측이 무작위가 아닐 수 있으면(특정 집단에 몰림) 완전 사례 분석의 편향을 한계에 적는다.

## 4. 통계 분석 판단 기준 (세부: `references/test-selection.md`)
- 검정은 **질문 × 설계(독립/대응·반복) × 결과 유형(연속/순서/이진/횟수/생존)**으로 고른다. 데이터를 보고 나서 결과가 좋은 검정을 고르지 않는다.
- 두 집단 평균 비교는 **Welch t-검정을 기본**으로 한다(등분산 가정 불필요). 정규성 사전검정 결과로 검정을 갈아타는 2단계 절차는 쓰지 않는다. 분포가 심하게 치우쳤거나 순서형이면 처음부터 순위 기반 검정이나 부트스트랩 CI를 쓰되, 순위 검정은 평균이 아닌 다른 것(확률적 우위·대칭 중심)을 검정한다는 점을 밝힌다.
- 가정은 검정 통계량 대신 **그림(잔차 그림, Q-Q plot)**과 설계 지식으로 판단한다. 표본이 크면 정규성 검정은 사소한 이탈도 유의하게 나온다.
- **p-value만 쓰지 않는다.** 효과 크기(Cohen's d/Hedges' g, 순위양분상관, 오즈비, R² 등)와 95% 신뢰구간을 함께 쓰고, 효과 크기는 계산한 지표 이름을 밝힌다.
- **여러 검정을 하면 보정한다.** 소수의 확증 가설은 Holm, 다수의 탐색 비교는 Benjamini–Hochberg(FDR). 몇 번 검정했는지 보고한다.
- 회귀는 진단(잔차, 이분산 → 강건 표준오차, 다중공선성, 영향점)을 하고, 반복측정·군집 데이터는 혼합효과 모형이나 GEE를 쓴다(`references/regression-mixed-causal.md`).
- "유의하지 않음" ≠ "차이 없음". 동등성을 주장하려면 동등성 검정(TOST)이나 CI가 미리 정한 허용 범위 안인지 보인다.

## 5. ML/DL 평가 판단 기준 (세부: `references/ml-evaluation.md`, `references/model-comparison.md`)
- **베이스라인은 두 층**: (1) 하한 확인용(다수 클래스·평균 예측·계절 naive), (2) **강한 베이스라인**(표 데이터는 튜닝한 GBDT, 텍스트는 같은 크기의 사전학습 모델 미세조정 등 해당 분야 표준). 약한 베이스라인만 이기는 것은 기여가 아니다.
- **튜닝 공정성**: 제안 모델과 베이스라인에 같은 탐색 예산·같은 검증 방식을 쓴다. 탐색 공간과 시도 횟수를 보고한다.
- 하이퍼파라미터를 CV로 고르고 그 CV 점수를 성능으로 보고하면 낙관 편향이 생긴다 → 별도 테스트 세트 또는 중첩 CV.
- **여러 시드(기본 5개) 평균 ± 표준편차**를 보고하되, 우열 주장은 같은 시드·같은 fold에서의 **쌍체 차이와 그 CI**로 한다. CV fold 점수에 일반 t-검정을 쓰지 않는다(fold가 독립이 아니라 낙관적). 보정 t-검정·데이터셋 간 Wilcoxon 등은 `references/model-comparison.md`.
- **지표는 문제에 맞게**: 불균형이면 accuracy 단독 금지 → PR-AUC(기준선 = 양성 비율), balanced accuracy, MCC, 클래스별 재현율. 임계값은 검증 세트에서 정한다. 확률을 쓰면 보정(Brier score, reliability diagram)을 본다.
- **애블레이션**: 주장하는 각 구성 요소를 하나씩 빼서 같은 설정·같은 시드로 비교한다.
- **오류 분석**: 평균 점수 외에 어디서 틀리는지(클래스·하위집단·길이·시간대별) 본다.
- **연산 비용**: 파라미터 수, 학습·추론 시간, 하드웨어, 전체 실험(튜닝 포함) GPU 시간을 기록한다.

## 6. 데이터 유형별 핵심
- **표 데이터**: 범주형 고유값이 많으면 타깃 인코딩은 fold 내부에서만. 시간 정보가 숨어 있으면(ID 순서, 수집일) 무작위 분할이 누수가 될 수 있다.
- **시계열·센서**: 롤링(확장) 원점 평가, gap, 피험자 분할. 자기상관이 있으면 관측치를 독립으로 가정한 검정이 무효다. 세부는 `references/timeseries.md`.
- **텍스트·LLM**: n-gram 지표(BLEU/ROUGE)는 의미 품질의 대리 지표일 뿐 → 사람 평가나 과제 지표 병행. LLM 평가자는 위치·길이·자기 선호 편향을 통제한다. 프롬프트 민감도를 보고한다. 세부는 `references/nlp.md`.

## 7. 실행하고 보고한다
- **실행하지 않은 결과를 보고하지 않는다.** 수치·그래프는 실제로 돌린 출력만 쓴다.
- 실행하지 못했으면(시간, GPU, 데이터 없음) 그렇다고 말하고, 예상치는 예상치라고 표시한다.
- 오래 걸리는 학습은 작은 샘플로 먼저 돌려서 코드가 끝까지 도는지 확인한 뒤 전체를 실행한다.
- 실패한 실험·제외한 실행도 기록에 남긴다. 좋은 시드·좋은 실행만 골라 보고하지 않는다.

## 8. 결과 보고 (세부: `references/reporting.md`)
기본 형태는 다음 세 가지다.
1. **요약 문단**: 핵심 결과를 몇 줄로. 효과의 크기와 불확실성, 그리고 무엇을 주장할 수 **없는지**까지.
2. **표**: CSV로 저장하고 대화에는 마크다운 표로(`templates/aggregate_results.py`).
3. **논문용 그림**: PDF(벡터)와 PNG(300dpi)로 저장(`templates/save_figure.py`). 축 이름·단위·범례를 넣고, 색만으로 구분하지 않는다(선 모양·마커 병행). 오차 막대가 SD·SE·CI 중 무엇인지 캡션에 적는다.

반드시 포함할 것:
- **통계**: 효과 크기와 95% 신뢰구간, 사용한 검정 이름과 이유, 다중 비교 보정 방법, 분석 단위와 n.
- **ML/DL**: 여러 시드(기본 5개) 결과의 평균 ± 표준편차, 쌍체 차이와 CI, 분할 방식.
- **베이스라인 비교**: 하한 베이스라인과 강한 베이스라인 둘 다, 같은 조건으로.
- **가정과 한계**: 가정 확인 결과, 데이터·표본의 한계, 일반화 범위, 사후·탐색 분석 표시.

## 완료 기준
마치기 전에 스스로 확인한다.
- [ ] 코드가 처음부터 끝까지 실제로 실행됐고, 보고한 수치는 그 출력과 일치한다. 빠진 실행·NaN·중복은 조용히 평균에서 빠지지 않고 보고됐다.
- [ ] 분석 단위·독립성을 밝혔고, 반복측정·군집 구조를 독립 표본으로 다루지 않았다.
- [ ] 분할 방식과 전처리 순서에 누수가 없다(시계열은 시간 순 분할, 필요 시 그룹 분할·gap). 테스트 세트는 한 번만 썼다.
- [ ] 전처리로 바뀐 내용(제거·대체 건수, 전후 개수)을 보고했다.
- [ ] 시드가 고정됐고, 설정·결과·코드 버전·환경이 기록됐다. 원본 데이터는 그대로다.
- [ ] 효과 크기·신뢰구간(통계) 또는 평균±표준편차와 쌍체 차이(ML)가 있고, 여러 검정은 보정했다.
- [ ] 하한·강한 베이스라인과 같은 조건(튜닝 예산·분할·시드)으로 비교했다.
- [ ] 지표가 문제(불균형·보정 필요 여부)에 맞고, 가정·한계·주장할 수 없는 것을 적었다.
