# 가상 사용자 사전 조사 매뉴얼

> **팀으로 진행:** `team-orchestration`의 "서비스 기획" 구성. scout = 분포 근거 조사, builder = 초안 작성, 오케스트레이터 = 검토 화면·종합, Codex = 질문지 사전 검사와 종합 검증.

사용자는 **아이디어만 주고, 검토 화면에서 한 번 승인**한다. 서비스 설명·분포·질문지는 매번 Claude가 만든다.
스크립트 경로의 `$CLAUDE_SETTINGS_DIR`은 설정 저장소 위치다(기본 `~/claude-settings`). 이하 `S="$CLAUDE_SETTINGS_DIR/skills/synthetic-user-research/scripts"`.

근거: Random Silicon Sampling(Sun et al., 2024, arXiv:2402.18144). 집단 분포에서 뽑은 가상 응답자는 **전체 분포**를 꽤 재현하지만, 하위집단을 과장하고, 애매한 집단(무당파)을 못 맞추고, 민감한 주제에서 무해한 답으로 쏠리며, 약 200명 아래에서 불안정했다. 새 서비스 기능은 학습 데이터에 답이 없어 더 불리하다.

## 용도의 선
| 쓴다 | 쓰지 않는다 |
|---|---|
| 사용 시나리오·예외 상황 발굴, 불편함·이탈 이유 찾기, PRD 빈틈 점검, 실제 인터뷰 질문지 다듬기 | 수요 비율 추정("몇 %가 쓴다"), 가격·지불 의사, 기능 우선순위 확정, 논문·투자 자료의 "사용자 조사 결과" |

결과는 모두 **`[가설]`**이다. 고르기·척도 질문의 수치도 실제 비율이 아니다.

## 1단계 — 초안 자동 작성 (Claude 팀, 사용자 개입 없음)
산출물은 프로젝트 `docs/research/`.
1. **아이디어 파악**: 대화, 프로젝트 `CLAUDE.md`, `docs/prd.md`를 읽는다. 문제·대상·기능 후보가 불분명하면 합리적으로 가정하고 `[가정]`으로 표시한다(질문하지 않는다).
2. **분포 근거 조사** (scout): 대상 집단 규모·구성(통계청·KOSIS, 업계 보고서, 기존 사용자 데이터), 대상이 지금 쓰는 대안. 출처를 남긴다.
3. **`service.md`**: 페르소나에게 보여 줄 설명만. 문제, 서비스가 하는 일, 기능 후보 목록. 내부 목표·기대 수치·홍보 문구는 넣지 않는다.
4. **`persona-spec.json`** (형식은 `sample_personas.py` 상단 설명):
   - 기획 문서가 있으면 PRD의 세그먼트·우선 타깃에서 분포를 가져온다.
   - 변수 4~7개. 인구통계만이 아니라 **행동 변수**(지금 쓰는 대안, 문제를 겪는 빈도, 기술 친숙도, 결정·지불 주체 등)를 넣는다.
   - **비사용자·잠재 사용자·경쟁 서비스 만족자**를 분포에 포함한다.
   - 서로 연관된 변수(예: 직급×연령)는 `joint`로 묶어 비현실적 조합을 막는다.
   - 모든 분포에 `sources`(출처 또는 `[가정]`)를 단다.
   - 인원: 기본 40명(질적 탐색). 고르기·척도 수치를 진지하게 보려면 200명 이상이 필요하다.
5. **`questions.md`**: `questions-bank.md`에서 골라 서비스에 맞게 고친다. 8~12개. 과거 행동 → 대안·전환 → 서비스 반응(안 쓸 이유, `multi max=2` 맞교환) → 맥락. 고르기·척도는 3~4개 이내로.
   - 꼭 들어가야 할 교차 집단(예: AI도 관리 도구도 안 쓰는 사람, 경쟁 도구 만족자)은 `quotas`로 최소 인원을 지정한다.
6. **페르소나 생성**: `python3 "$S/sample_personas.py" docs/research/persona-spec.json docs/research/personas.json --search-seed`
   - `--search-seed`가 목표 분포에 가장 가까운 seed를 찾아 사양 파일에 기록한다. 같은 조합은 중복되지 않는다.

## 2단계 — Codex 사전 검사 (사용자 개입 없음)
```bash
"$CLAUDE_SETTINGS_DIR/scripts/codex-verify.sh" docs/research - -t survey --label 질문지-사전검사 -e high
```
브리핑에 검사 대상(`service.md`, `persona-spec.json`, `questions.md`)과 목적을 적는다. 지적은 수용하거나 근거를 대고 기각한다(`team-orchestration` 7절). 고친 뒤 페르소나를 다시 생성한다.

## 3단계 — 사용자 검토 (한 번)
`docs/research/review.md`를 만들어 **한 화면**으로 보여 주고 승인을 받는다. 승인 전에는 인터뷰를 실행하지 않는다.
```
# 가상 사용자 사전 조사 — 검토
## 무엇을 확인하려는가 (가설 후보 3~5개)
## 누구에게 묻는가 — 페르소나 N명
| 변수 | 분포 | 근거 |      ([가정]은 굵게)
뽑힌 인원 요약, 포함된 비사용자·잠재 사용자 비율
## 무엇을 보여 주는가 — service.md 전문
## 무엇을 묻는가 — 질문 목록(형식 표시)
## Codex 사전 검사 결과 — 지적과 처리(수용/기각)
## 외부 전송 — 서비스 설명과 질문이 Anthropic·OpenAI로 전송됨. 진행해도 되는지
## 예상 소요 — 두 모델 × N명, 약 X분
```
사용자가 고치라고 하면 반영하고, 바뀐 부분만 다시 보여 준다.

## 4단계 — 인터뷰 실행
```bash
python3 "$S/persona_interview.py" --personas docs/research/personas.json --service docs/research/service.md \
  --questions docs/research/questions.md --out-dir docs/research
```
- 기본: 1명씩 따로 호출(`--batch 1`), 동시 4개(`--workers 4`), Claude는 sonnet, Codex는 기본 모델. 40명이면 수 분~십여 분 → 백그라운드로 실행한다.
- 영어 서비스는 `--lang en`, 제품이 아닌 의견 설문은 `--frame survey`.
- 결과: `responses_claude.json`, `responses_codex.json`. 오류·누락이 있으면 그 페르소나만 다시 돌리거나 보고한다.

## 5단계 — 집계와 종합
1. **집계**: `python3 "$S/aggregate.py" --dir docs/research --by <핵심 변수>` → `aggregate.md`
   - 고르기·척도의 모델별 분포, 두 모델 간 χ²·KL, 하위집단별 응답, 쏠림(≥90%)·과장(하위집단 ≥95%) 경고.
   - 실제 조사 결과가 있으면 `--reference`로 비교한다.
2. **종합** `hypotheses.md` (오케스트레이터):
   - 열린 질문은 모델별로 따로 주제 코딩한다(builder 2명 병렬, 서로의 파일을 보지 않게: `themes_claude.md`, `themes_codex.md`). 한쪽에만 있다고 판단하기 전에 다른 쪽 코딩 파일 전체를 읽어 확인한다(키워드 검색만으로 판단하지 않는다). **두 모델 모두에서 나온 것만 가설로 채택**하고, 한쪽만이면 "약한 신호"로 둔다. 고르기·척도에서 두 모델 분포가 유의하게 다르면(p<0.05) 그 질문 결과는 신뢰도 "낮음".
   - 가설마다: 내용 · 근거(페르소나 ID, 모델별 인원) · 해당 집단 · 신뢰도(높음/중간/낮음) · 확인 방법.
   - 신뢰도를 낮추는 것: 쏠림·과장 경고, 애매한 집단(잠재·비사용자)의 응답, 한 특성으로만 설명되는 극단 응답.
   - "좋다/쓰겠다"는 수요 근거로 세지 않는다. 불편함·이탈 이유·현재 행동만 센다.
3. **Codex 검증**: `codex-verify.sh docs/research - -t plan,survey --label 종합-검증` — 종합이 응답·집계와 맞는지, 과장·누락이 없는지.

## 6단계 — 실제 확인 계획
- `interview-guide.md`: 신뢰도 높은 가설 3~5개를 확인할 **실제 사용자 5명 내외** 인터뷰 질문지와 모집 조건(비사용자 포함). 5명 인터뷰는 문제·사용성 발견용이지 수요 검증이 아니다.
- 실제 결과를 받으면 `hypotheses.md`에 확인/기각을 적고, 확인된 것만 `docs/prd.md`에 반영한다.

## 완료 기준
- [ ] 사용자에게 받은 입력은 아이디어와 검토 승인뿐이다(나머지는 Claude가 작성).
- [ ] 분포에 행동 변수와 비사용자·잠재 사용자가 있고, 모든 분포에 근거나 `[가정]`이 있다.
- [ ] Codex 사전 검사를 거쳐 지적을 처리했고, `review.md`로 사용자 승인을 받은 뒤 인터뷰했다.
- [ ] 두 모델 응답이 모두 있고 누락·형식 오류를 처리했다.
- [ ] 가설은 두 모델 공통 패턴만 채택했고, 각 가설에 근거 ID·인원·신뢰도가 있다. 쏠림·과장 경고를 반영했다.
- [ ] 종합을 Codex로 검증했고, 실제 사용자 확인용 질문지가 있다. 모든 결과에 `[가설]` 표시가 있다.
