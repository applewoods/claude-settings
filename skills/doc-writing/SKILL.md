# 문서 작성 매뉴얼

> **팀으로 진행:** 긴 문서(제안서·최종 보고서 등)나 근거 정리가 많은 일은 `team-orchestration`의 "문서·기획서" 구성으로 나눈다. scout = 자료 수집·요약, builder = 절별 초안, expert = 핵심 메시지·구성, verifier = 요청 사항 대조·근거 없는 주장 표시. 각 팀원은 이 매뉴얼을 따른다.

문서는 **읽는 사람이 무엇을 결정하거나 이해하게 할지**에서 시작한다. 문장을 다듬기 전에 "이 문서를 읽고 독자가 무엇을 하게 되는가"와 "그 근거가 문서 안에 있는가"를 먼저 본다.

## 경계
- 이 스킬: 내용을 **문서로 만드는 일**(구성, 문체, 근거 정리, 파일 형식).
- 연구 내용 자체(연구 질문, 기여, 실험 설계)는 `research-design`. 제안서의 연구 내용은 그 산출물(`docs/research-plan.md`)이 있으면 가져다 쓴다.
- 논문 원고·리뷰어 답변은 `paper-writing`, 서비스 PRD는 `service-planning`.
- 파일 만들기는 `anthropic-skills:docx`·`anthropic-skills:pptx` 스킬을 쓴다(이 매뉴얼은 내용과 구성, 그 스킬은 파일 형식).

## 1. 먼저 정한다 (모든 문서)
문서 앞에 아래를 짧게 적어 보여 준다. 모르는 칸은 `[가정]`으로 채운다.
- **독자**: 누가 읽는가(지도교수, 기업 담당자, 학회 청중 등). 전공자인지, 시간이 얼마나 있는지.
- **목적**: 독자가 읽고 나서 할 일(승인, 예산 결정, 진행 상황 이해, 협조 등).
- **핵심 메시지 한 문장**: 문서 전체를 한 문장으로. 이게 안 써지면 구성부터 다시 본다.
- **분량·형식 제약**: 쪽수·글자 수·발표 시간·양식 항목. 공고문·양식이 있으면 거기서 확인하고, 없으면 `[확인 필요]`.

## 2. 진행 순서: 메시지·목차 먼저
1. 위 1절 + **목차**를 먼저 보여 준다. 목차의 각 항목에 "이 절이 말할 것(한 줄)"을 붙인다. 짧은 문서(회의록, 메일, 1쪽 기획서)는 이 단계를 생략하고 바로 초안을 쓴다.
2. 확인을 받으면 본문을 쓴다. 확인을 받을 수 없는 상황이면 목차를 문서 앞에 둔 채 본문까지 쓰고, 목차를 `[가정]`으로 표시한다.
3. 수치·사실이 들어가는 문서는 본문 전에 **근거 표**를 만든다: `주장/수치 | 근거(파일·표·출처) | 상태(확인/확인 필요/근거 필요)`. 본문은 이 표에 있는 것만 쓴다.
4. 본문을 쓴 뒤 3절(문체)과 4절(근거)로 점검하고, 필요하면 `docx`·`pptx` 스킬로 파일을 만든다.

## 3. 문체 (세부: `references/style-ko.md`)
- **본문은 개조식이 기본이다.** 수준 기호 `□ → ○ → -`, 종결은 `~함 / ~임 / 명사형`으로 한 문서 안에서 통일한다. 서술식 양식이면 그 양식을 따른다.
- 한 항목에 한 내용. 한 항목이 2줄을 넘으면 나눈다. 같은 말을 절마다 반복하지 않는다.
- **과장·미사여구를 쓰지 않는다.** "혁신적", "획기적", "세계 최초", "극대화" 같은 말은 근거(수치·비교 대상)로 바꾸거나 뺀다. "최초"는 근거가 있어도 확인 범위를 밝힌다.
- **영어는 꼭 필요할 때만.** 고유명사·모델명·표준 용어는 원어, 우리말로 충분한 일반어는 우리말. 약어는 처음 나올 때 풀어 쓴다.
- **형식을 남발하지 않는다.** 굵게는 결론·핵심 수치에만, 이모지 금지, 한 줄짜리 목록을 잘게 쪼개지 않는다.

## 4. 근거·수치
- 문서에 넣는 수치는 근거 표의 출처와 대조한다. 합계·비율·증감률은 직접 다시 계산해 맞춘다(예: 예산 합계, 일정 기간, 달성률).
- 지어낸 실적·수치·인용을 넣지 않는다. 비어 있으면 `[확인 필요]`·`[근거 필요]`로 남긴다. 표시가 남아 있으면 "초안"으로 보고한다.
- 목표·성과는 **측정 가능한 지표**로 쓴다: 지표 이름, 현재값(기준선), 목표값, 측정 방법, 시점.
- 기대효과·활용 계획은 "누가, 무엇에, 어떻게 쓰는가"로 쓴다. 근거 없는 경제 효과 수치는 만들지 않는다.

## 5. 문서 종류별 (해당하는 것만 읽는다)
| 문서 | 핵심 | 읽을 것 |
|---|---|---|
| 연구과제 제안서·계획서 | 평가 기준 ↔ 목차 대응, 필요성 → 목표(정량) → 내용·방법 → 추진 체계·일정 → 기대효과 | `references/proposal.md` |
| 연구·실적·기술 보고서 | 요약 먼저, 계획 대비 실적 표, 미달 사유와 대책, 다음 계획 | `references/report.md` |
| 발표자료 | 슬라이드 하나에 메시지 하나, 제목을 문장으로, 청중별 깊이 | `references/slides.md` |
| 기획서·회의록·메일 | 요청·결정을 첫 줄에, 회의록은 결정·할 일·담당·기한 | `references/business.md` |

## 6. 파일로 낼 때
- Word는 `docx` 스킬, PowerPoint는 `pptx` 스킬로 만든다. 기관 양식 파일이 있으면 그 파일을 기반으로 채우고 스타일을 바꾸지 않는다.
- 파일을 만든 뒤 직접 열어(또는 변환해) 확인한다: 목차·번호, 표 깨짐, 글꼴, 쪽수·슬라이드 수가 제약 안인지.
- 기존 파일을 덮어쓰지 않는다. 새 이름으로 저장하고 알린다.

## 완료 기준
- [ ] 독자·목적·핵심 메시지 한 문장·분량 제약이 문서 앞(또는 답변 앞)에 있다.
- [ ] 긴 문서는 목차(절마다 한 줄 메시지)를 먼저 보여 줬다(확인 못 받았으면 `[가정]` 표시).
- [ ] 모든 수치가 근거 표와 일치하고, 합계·비율을 다시 계산했다. 지어낸 수치·실적·인용이 없다.
- [ ] 개조식·종결어미가 통일돼 있고, 과장어·불필요한 영어·형식 남발이 없다(`references/style-ko.md` 점검표).
- [ ] 문서 종류별 필수 요소(`references/` 해당 파일의 점검표)를 확인했다.
- [ ] 분량·형식 제약을 지켰다(확인 못 한 제약은 `[확인 필요]`).
- [ ] 파일로 냈다면 직접 열어 확인했다. 표시가 남아 있으면 "초안"으로 보고했다.
