# 연구·실적·기술 보고서

## 1. 구조 (결론 먼저)
1. **요약(1쪽 이내)**: 이번 기간의 핵심 성과 3개 이내, 계획 대비 달성 정도, 문제와 대응, 다음 기간 계획. 요약만 읽어도 상황을 판단할 수 있게 쓴다.
2. **계획 대비 실적 표**: `목표(지표) | 계획 | 실적 | 달성 여부 | 근거(파일·그림·표 번호)`. 달성률은 직접 계산한다.
3. **세부 성과**: 목표별로 무엇을 했고 결과가 무엇인지. 결과는 수치·그림과 함께, 해석은 결과와 구분한다.
4. **미달·변경 사항**: 무엇이 왜 늦거나 바뀌었는지, 영향, 대책과 새 일정. 숨기지 않는다. 미달을 성과처럼 포장하지 않는다.
5. **다음 계획**: 다음 기간 목표와 확인 가능한 산출물.
6. **부록**: 상세 실험 설정, 데이터, 산출물 목록.

## 2. 쓰는 원칙
- 실적은 **확인 가능한 산출물**로 쓴다: 논문(게재/투고/작성 중 구분), 코드 저장소, 데이터셋, 시연, 특허 출원 번호. 상태를 부풀리지 않는다(투고를 게재로 쓰지 않음).
- 수치는 원자료(결과 파일·표)와 대조한다. 이전 보고서와 숫자가 바뀌었으면 이유를 적는다.
- 독자별로 깊이를 조절한다: 기업 담당자에게는 기술 세부보다 "무엇이 가능해졌고 언제 쓸 수 있는지", 지도교수에게는 막힌 부분과 결정이 필요한 사항을 앞에.
- 결정이 필요한 사항은 따로 모아 "요청 사항"으로 맨 앞이나 맨 끝에 둔다.

## 점검표
- [ ] 요약 1쪽에 성과·달성 정도·문제·다음 계획이 있다.
- [ ] 계획 대비 실적 표가 있고 달성률을 다시 계산했다.
- [ ] 미달·변경 사항과 대책이 있다(없으면 "없음"을 명시).
- [ ] 실적의 상태(게재/투고/진행)가 정확하고 근거 파일과 맞다.
- [ ] 결정이 필요한 사항이 따로 정리돼 있다.
