# AI 기능 UX

**언제 읽나:** LLM·모델이 생성·요약·추천·분류·자동 입력하는 기능을 설계할 때(챗봇, RAG 검색, 자동 태깅, 예측 결과 화면 등).
**연구 데모:** 1·2절(기대 설정, 근거)만 해도 시연 신뢰도가 크게 오른다. 단, 데모 결과를 실제 성능처럼 보이게 꾸미지 않는다.

## 1. 기대를 맞춘다
- 무엇을 할 수 있고 **무엇을 못 하는지** 첫 화면·입력칸 근처에 짧게. 예시 질문/입력 2~3개로 범위를 보여 준다.
- AI가 만든 결과임을 표시한다(라벨·아이콘). 사람이 쓴 것과 섞일 때 특히.
- 결과가 틀릴 수 있음을 알리되, 모든 화면에 경고문을 반복하지 말고 결과가 중요한 곳(의료·금전·법률·연구 수치)에 구체적으로.

## 2. 근거와 불확실성
- **출처를 보여 준다(RAG):** 문장 옆 인용 번호 → 클릭하면 원문 해당 부분. 출처가 없는 주장은 구분해서 표시하거나 생성하지 않게 한다.
- 불확실성은 사용자가 행동을 바꿀 수 있는 형태로: 원시 확률(0.73)보다 "확신 낮음 · 검토 필요" 같은 구간 + 이유. 확률을 보여 준다면 보정(calibration)된 값일 때만 `[판단 기준: 보정되지 않은 점수를 %로 보여 주면 과신을 부른다]`.
- 모르는 것은 모른다고: "찾은 자료에 답이 없어요" + 다른 경로(검색어 바꾸기, 사람에게 문의)가 지어낸 답보다 낫다.

## 3. 사용자가 통제한다
- **고칠 수 있게:** 결과를 바로 편집, 부분 재생성, 다른 안 보기. 자동 입력은 제안 상태(회색·점선)로 두고 사용자가 수락.
- **되돌릴 수 있게:** AI가 바꾼 것은 버전/이전 상태로 복귀. 일괄 자동 적용은 미리보기 → 적용 → 실행 취소.
- **중요한 행동은 사람이 확정:** 보내기·삭제·결제·외부 공개는 AI가 제안까지만.
- 피드백 수단(좋아요/싫어요 + 이유 선택)은 실제로 개선에 쓸 때만 둔다.

## 4. 기다림과 실패
- 스트리밍 출력으로 첫 반응을 빠르게. 생성 중 **중단 버튼**.
- 긴 작업은 단계 표시("문서 검색 중 → 요약 중"). 단, 실제 처리 단계와 다른 가짜 단계 표시는 하지 않는다.
- 실패 유형별 안내: 시간 초과, 사용량 한도, 정책상 거절, 입력이 너무 김 — 각각 사용자가 할 수 있는 일이 다르다.
- 같은 입력에 결과가 매번 다를 수 있음을 고려: 이전 결과를 잃지 않게 기록.

## 5. 대화형(채팅) UI에 대해
- 채팅이 기본 답이 아니다. 과업이 정형화돼 있으면(필터, 양식) 버튼·폼이 더 빠르고 정확하다. 채팅은 열린 질문에.
- 답변 안의 행동(표 내보내기, 적용하기)은 버튼으로 제공.
- 긴 답변은 요약 먼저, 상세는 펼치기.

## 6. 개인정보·안전
- 입력이 모델 학습·외부 전송에 쓰이는지 입력칸 근처에 알린다. 민감 정보 입력을 유도하지 않는다.

## 흔한 실수
- AI 답을 사람 답과 같은 모양·같은 확신으로 표시.
- 출처 링크가 있지만 실제 근거 문장과 연결되지 않음.
- 재생성하면 이전 결과가 사라짐.
- 오류 시 "문제가 발생했어요"만 보이고 입력도 지워짐.
