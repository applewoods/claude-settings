# 모바일 UX

**언제 읽나:** 모바일 웹(반응형 포함)이나 React Native/Expo 앱 화면을 설계할 때.
**연구 데모:** 데스크톱 시연용이면 "모바일 폭에서 깨지지 않음" 확인만 한다.

## 1. 손과 화면
- 한 손 사용이 많다. 주요 행동(저장, 다음, 추가)은 **화면 아래쪽**, 엄지가 닿기 쉬운 영역에. 위험한 행동(삭제)은 실수로 닿기 어려운 곳에.
- 화면 위쪽 모서리는 닿기 어렵다 → 자주 쓰는 기능을 왼쪽 위 메뉴에만 두지 않는다.
- 터치 영역: 이 프로젝트 기본 44×44px. 플랫폼 권장은 iOS 44×44pt, Android(Material) 48×48dp `[확인 필요: 이번 작업에서 Apple HIG·Material 공식 페이지를 다시 열어 보지 못함]`. 눈에 보이는 아이콘이 작아도 눌리는 영역(padding)을 키운다. 인접 대상 사이 간격 8px 안팎.
- 노치·홈 인디케이터: `env(safe-area-inset-*)`(웹) / `SafeAreaView`(RN). 하단 고정 버튼이 홈 인디케이터와 겹치지 않게.
- 가상 키보드가 올라오면 입력칸과 제출 버튼이 가려지지 않는지 확인한다(웹은 `100vh` 대신 `100dvh`).

## 2. 제스처
- 제스처는 숨겨진 기능이다. **모든 제스처에 눈에 보이는 대안**(버튼·메뉴)을 둔다. WCAG 2.5.1(경로 제스처), 2.5.7(드래그) 대응이기도 하다.
- 스와이프 삭제 같은 파괴적 제스처는 되돌리기와 함께.
- 시스템 제스처와 겹치지 않게: iOS 화면 왼쪽 가장자리 스와이프 = 뒤로 가기, 하단 가장자리 = 홈. 가로 캐러셀을 화면 가장자리까지 붙이면 충돌한다.

## 3. 플랫폼 관례 (앱이면 섞지 않는다)
| 항목 | iOS | Android |
|---|---|---|
| 뒤로 가기 | 왼쪽 위 뒤로 버튼 + 가장자리 스와이프 | 시스템 뒤로(제스처/버튼) — 앱이 막지 않기 |
| 최상위 내비게이션 | 하단 탭 바 | 하단 내비게이션 바(Navigation bar) |
| 주요 행동 | 내비게이션 바 오른쪽 버튼 | FAB 또는 상단 앱 바 |
| 선택 메뉴 | 액션 시트(하단) | 메뉴·하단 시트 |
| 알림 문구 | 알림(alert) | 스낵바(되돌리기 포함 가능) |
- React Native/Expo는 `react-navigation` 기본 동작이 플랫폼 관례를 따르므로 임의로 바꾸지 않는다.
- 모바일 웹은 플랫폼 중립으로 두되, 브라우저 뒤로 가기가 모달·하단 시트를 닫게 한다.

## 4. 레이아웃
- 모바일 우선으로 정보의 우선순위를 정한 뒤 데스크톱으로 넓힌다(데스크톱을 줄이면 중요한 것이 아래로 밀린다).
- 표는 모바일에서 카드 목록으로 바꾸거나 핵심 열만 남기고 나머지는 상세로 → `data-dense.md`.
- 가로 스크롤은 의도한 곳(캐러셀, 넓은 표)에만. 페이지 전체 가로 스크롤은 버그다.
- 글자 크기: 본문 16px 이상. iOS Safari는 16px 미만 입력칸에 포커스하면 화면을 확대한다.
- 시스템 글자 크기 확대(Dynamic Type, Android 글꼴 크기)에서 깨지지 않는지 확인한다(고정 높이 금지).

## 5. 성능과 상황
- 느린 네트워크·오프라인을 가정한다: 로딩 상태, 재시도, 입력 임시 저장.
- 밖에서 쓰는 앱이면 햇빛 아래 가독성 → 대비를 기준보다 여유 있게.

## 흔한 실수
- 데스크톱 hover에만 정보를 숨김(모바일엔 hover가 없다).
- 하단 고정 버튼이 키보드나 홈 인디케이터에 가려짐.
- 작은 아이콘 버튼 여러 개를 붙여 놓아 오터치.
- 안드로이드에서 시스템 뒤로 가기를 눌렀는데 앱이 종료되거나 아무 반응 없음.
