# 접근성 — WCAG 2.2 AA 핵심

**언제 읽나:** 모든 화면을 만들 때 훑고, 출시 서비스는 배포 전에 정독한다. 최종 점검은 `design:accessibility-review`와 `web-design-guidelines`.
**출처:** W3C WCAG 2.2 (https://www.w3.org/TR/WCAG22/), 2026-10-17 확인. 아래 수치·수준은 이 문서에서 직접 대조했다.
**주의:** 자동 검사 도구(axe, Lighthouse)는 일부 문제만 잡는다. 키보드 조작과 스크린 리더 확인은 직접 해야 한다.

## 1. 수치 기준 (헷갈리기 쉬운 것)
| 기준 | 수준 | 내용 |
|---|---|---|
| 1.4.3 Contrast (Minimum) | AA | 글자 4.5:1, **큰 글자 3:1** (큰 글자 = 18pt 이상 또는 14pt 굵게. CSS로 대략 24px / 18.66px 굵게) |
| 1.4.11 Non-text Contrast | AA | UI 요소(입력칸 경계, 체크박스, 아이콘 버튼)와 의미 있는 그래픽은 인접 색 대비 **3:1** |
| 1.4.4 Resize Text | AA | 보조 기술 없이 **200%** 확대해도 내용·기능 유지 |
| 1.4.10 Reflow | AA | **320 CSS px** 폭에서 가로 스크롤 없이 사용(표·지도처럼 2차원이 필요한 것은 예외) |
| 1.4.12 Text Spacing | AA | 줄 높이 1.5배, 문단 간격 2배, 글자 간격 0.12배, 단어 간격 0.16배로 바꿔도 깨지지 않을 것 → 높이를 고정하지 말 것 |
| 2.5.8 Target Size (Minimum) | AA | 터치·클릭 대상 **24×24 CSS px** 이상. 예외: 간격(Spacing), 같은 기능의 다른 대상(Equivalent), 문장 안 링크(Inline), 브라우저 기본 컨트롤(User Agent Control), 필수(Essential) |
| 2.5.5 Target Size (Enhanced) | **AAA** | 44×44 CSS px |
| 2.2.1 Timing Adjustable | A | 시간 제한은 끄기/조정/연장 가능해야. 연장은 만료 전 경고 후 **최소 20초** 동안 간단한 동작으로, 최소 10회. 20시간 넘는 제한은 예외 |
| 2.3.1 Three Flashes | A | 1초에 3번 넘게 번쩍이지 않기 |

> **이 프로젝트 기본값은 WCAG 최소보다 엄격하다:** 글자 대비는 큰 글자도 4.5:1, 터치 대상은 44px. 위 표의 WCAG 최소값(3:1, 24px)은 기준 설명일 뿐 기본값이 아니다. 조밀한 데스크톱 표처럼 44px가 어려운 화면은 임의로 낮추지 말고 사용자에게 묻는다.

## 2. WCAG 2.2에서 새로 생긴 기준 (2.1까지 알던 사람이 놓치는 것)
| 기준 | 수준 | 실무 의미 |
|---|---|---|
| 2.4.11 Focus Not Obscured (Minimum) | AA | 포커스된 요소가 고정 헤더·쿠키 배너·채팅 버튼에 **완전히** 가려지면 안 됨 → `scroll-padding-top` 등 |
| 2.5.7 Dragging Movements | AA | 드래그로 하는 기능(순서 바꾸기, 슬라이더, 지도)은 드래그 없는 단일 포인터 대안 필요(위/아래 버튼, 값 입력) |
| 2.5.8 Target Size (Minimum) | AA | 위 표 참고 |
| 3.2.6 Consistent Help | A | 도움말·문의 수단이 여러 페이지에 있으면 같은 상대 위치에 |
| 3.3.7 Redundant Entry | A | 같은 과정에서 이미 입력한 정보는 자동 채움 또는 선택 가능하게 |
| 3.3.8 Accessible Authentication (Minimum) | AA | 로그인에 인지 테스트(비밀번호 기억, 퍼즐) 강요 금지 → 붙여넣기·비밀번호 관리자 허용, 대안 제공. 객체 인식·본인이 올린 콘텐츠 식별은 예외 |
- 4.1.1 Parsing은 WCAG 2.2에서 **삭제**됐다. 오래된 체크리스트에 있으면 무시한다.

## 3. 자주 위반되는 A/AA 기준
- 1.4.1 Use of Color (A): 색만으로 의미 전달 금지. 오류 칸은 빨간 테두리 + 아이콘 + 문구. 차트 계열은 색 + 모양/라벨.
- 2.1.1 Keyboard (A): 모든 기능이 키보드로. 커스텀 드롭다운·모달·드래그가 단골 위반.
- 2.4.3 Focus Order (A): 모달 열면 모달 안으로, 닫으면 연 버튼으로 포커스 복귀. 모달 밖으로 Tab이 새지 않게.
- 2.4.7 Focus Visible (AA): `outline: none` 금지. 바꾸려면 `:focus-visible`로 더 잘 보이게.
- 2.5.1 Pointer Gestures (A): 핀치·스와이프 등 경로 제스처에는 단일 포인터 대안.
- 2.5.3 Label in Name (A): 보이는 라벨 글자가 접근성 이름에 포함돼야(음성 조작 사용자).
- 1.4.13 Content on Hover or Focus (AA): 툴팁은 Esc로 닫히고, 마우스를 툴팁 위로 옮겨도 유지.
- 3.3.1 Error Identification (A) / 3.3.3 Error Suggestion (AA): 오류를 글자로 알리고, 고칠 방법을 제안.
- 4.1.3 Status Messages (AA): "저장됨", "검색 결과 12건" 같은 상태 메시지는 포커스 이동 없이 스크린 리더가 읽게(`role="status"` / `aria-live="polite"`).
- 이미지 대체 텍스트, 입력칸 라벨 연결, 아이콘 버튼 `aria-label`, 페이지 `lang="ko"`.

## 4. 직접 확인 절차 (10분)
1. Tab만으로 핵심 과업 끝내기 — 포커스가 보이는가, 순서가 자연스러운가, 가려지지 않는가.
2. 브라우저 200% 확대, 그리고 320px 폭 — 잘리거나 겹치는가.
3. 대비 측정 — 보조 글자, placeholder, 비활성 버튼(비활성은 대비 요구 예외지만 읽혀야 할 정보면 대비 확보), 다크 모드.
4. macOS VoiceOver(Cmd+F5)로 주요 화면 한 번 — 버튼 이름, 상태 메시지, 제목 구조.
5. `prefers-reduced-motion` 켜고 움직임 확인.

## 흔한 실수
- shadcn/ui를 썼으니 접근성은 된다고 가정 — 컴포넌트는 기반일 뿐, 라벨·이름·대비는 직접 챙겨야 한다.
- `div`에 `onClick` → 키보드·스크린 리더 불가. `button`을 쓴다.
- 대비를 라이트 모드에서만 측정.
