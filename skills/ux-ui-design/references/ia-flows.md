# 사용자 흐름·정보 구조(IA)·내비게이션

**언제 읽나:** 화면이 5개 이상, 메뉴 구조를 새로 잡을 때, "어디서 뭘 해야 할지 모르겠다"는 피드백이 있을 때.
**연구 데모:** 1절(핵심 흐름)만 하면 된다.

## 1. 사용자 흐름
- 과업 1개 = 흐름 1개. 형식: `진입 → 단계 → 판단(분기) → 완료 → 다음 행동`.
- 각 단계마다 적는다: 사용자가 **알아야 하는 것**, **결정할 것**, **실패할 수 있는 지점**.
- 분기마다 실패 경로를 적는다: 입력 오류, 권한 없음, 데이터 없음, 중복, 시간 초과, 중간 이탈(돌아오면 어디서 이어지나).
- 판단 기준
  - 핵심 과업의 단계 수를 센다. 줄일 수 있는 단계(재입력, 불필요한 확인, 미리 알 수 있는 값 묻기)를 먼저 없앤다.
  - "완료" 뒤에 무엇을 할지 화면이 알려 주는가(막다른 화면 금지).
  - 기획 문서의 화면 흐름과 어긋나면 기획을 고치자고 제안한다(조용히 바꾸지 않는다).

## 2. 정보 구조
- 사용자가 쓰는 말로 이름 짓는다. 내부 조직명·DB 테이블명·개발 용어 금지.
- 묶는 기준을 하나로: 대상(프로젝트별) / 과업(만들기·분석·공유) / 시간(최근·보관) 중 하나를 주축으로. 섞이면 길을 잃는다.
- 깊이와 너비: 최상위 메뉴는 대략 5~7개 안쪽, 3단계보다 깊으면 검색·바로가기를 추가한다 `[경험칙, 공식 수치 아님]`.
- 같은 대상은 한 곳에만 둔다. 두 메뉴에 같은 기능이 있으면 이름이 같아야 하고 결과도 같아야 한다.
- 검증(출시 서비스): 카드 분류(사용자가 항목을 직접 묶어 보게 함) 또는 트리 테스트(메뉴만 보고 "X는 어디 있을까요?" 찾게 함). 소수 인원으로도 큰 문제는 드러난다.

## 3. 내비게이션 패턴 고르기
| 상황 | 추천 |
|---|---|
| 데스크톱 앱, 메뉴 5개 이상 | 왼쪽 사이드바(접기 가능) + 상단에 현재 위치 |
| 데스크톱 앱, 메뉴 3~4개이고 늘어날 계획이 없음 | 상단 탭/바 (늘어날 예정이면 처음부터 사이드바) |
| 모바일 앱, 최상위 3~5개 | 하단 탭 바. 햄버거 메뉴에 핵심 기능 숨기지 않기 |
| 깊은 계층 | 브레드크럼 + 뒤로 가기가 예측 가능하게 |
| 항목 상세 ↔ 목록을 자주 오감 | 데스크톱은 목록-상세 2단, 모바일은 화면 전환 |

- 현재 위치를 항상 표시한다(활성 메뉴, 제목, 브레드크럼).
- URL은 상태를 담는다: 필터·탭·페이지·선택 항목이 URL에 있어야 새로고침·공유·뒤로 가기가 깨지지 않는다.
- 브라우저 뒤로 가기가 모달·탭 전환에서 예상대로 동작하는지 확인한다.

## 흔한 실수
- 기능 목록을 그대로 메뉴로 만듦(사용자 과업과 무관한 구조).
- "더보기"·햄버거에 자주 쓰는 기능을 숨김.
- 설정 화면이 기능별로 흩어져 있거나, 반대로 모든 것을 설정에 몰아넣음.
- 필터 상태가 URL에 없어 새로고침하면 초기화됨.
