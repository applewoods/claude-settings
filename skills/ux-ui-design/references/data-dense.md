# 데이터가 많은 화면 — 표·대시보드·관리 화면

**언제 읽나:** 표, 대시보드, 관리자 화면, 실험 결과 뷰어를 설계할 때. 차트 자체의 색·형태는 `dataviz` 스킬을 따른다.

## 1. 대시보드
- **질문부터:** 이 화면을 여는 사람이 답을 얻고 싶은 질문 3개를 적는다. 질문에 답하지 않는 위젯은 뺀다.
- 위에서 아래로 "요약 → 추세 → 상세". 첫 화면은 "지금 행동해야 할 것"(이상값, 실패, 마감)을 먼저.
- 숫자 하나만 보여 주지 않는다: 비교 기준(지난주 대비, 목표 대비, 기준선)이 있어야 의미가 생긴다.
- 기간·필터는 화면 상단 한 곳, 모든 위젯에 같은 조건이 적용됨을 표시. 조건은 URL에.
- 데이터 신선도 표시("5분 전 갱신"). 지연·누락 데이터는 0과 구분해서 표시("—" 또는 "수집 안 됨").
- 장식용 차트 금지: 같은 정보를 표나 숫자 하나로 더 빨리 읽을 수 있으면 그쪽.

## 2. 표
- 정렬: **숫자는 오른쪽**, 글자는 왼쪽, 짧은 상태값은 가운데 또는 왼쪽. 숫자 열은 `tabular-nums`, 소수 자릿수 통일, 단위는 헤더에.
- 밀도: 기본/조밀 두 가지 행 높이를 제공할 수 있다. 조밀 모드에서도 클릭 대상은 24px 이상(AA).
- 헤더 고정, 첫 열(식별자) 고정을 고려. 가로 스크롤이 생기면 스크롤 가능함이 보여야 한다.
- 정렬·필터 상태를 헤더에 표시(화살표, 필터 아이콘 활성). 현재 정렬 기준이 무엇인지 항상 보이게.
- 긴 텍스트: 한 줄 줄임 + 전체는 툴팁/상세. 식별자(ID, 파일명)는 가운데 줄임이 나을 때가 많다.
- 행 선택과 일괄 작업: 선택 개수 표시, "전체 선택"이 현재 페이지인지 전체 결과인지 명확히.
- 행 클릭 = 상세 이동이면 행 안의 버튼 클릭과 충돌하지 않게. 키보드로도 이동 가능하게.
- 페이지네이션 vs 무한 스크롤: 특정 행을 다시 찾거나 비교하는 업무는 페이지네이션(+ 총 건수), 훑어보는 피드는 무한 스크롤.
- 많은 행(수천 이상)은 서버 정렬·필터 또는 가상 스크롤. 성능은 `frontend` 스킬 기준.
- 모바일: 열을 다 보여 주지 않는다. 핵심 2~3개 열의 카드 목록 → 탭하면 상세.

## 3. 관리·편집 화면
- 보기와 편집 구분: 인라인 편집은 저장 상태(저장 중/저장됨/실패)를 칸마다 표시.
- 일괄 변경·삭제는 대상 수를 보여 주고 되돌리기 제공.
- 감사 정보(누가, 언제 바꿨는지)를 상세에 둔다(내부 도구·출시 서비스).

## 흔한 실수
- KPI 카드 8개를 같은 크기로 나열 — 무엇이 중요한지 없음.
- 숫자 왼쪽 정렬, 자릿수 제각각.
- 0과 "데이터 없음"을 같은 0으로 표시.
- 필터가 적용 중인데 표시가 없어 "데이터가 사라졌다"고 오해.
