# 상호작용 원칙과 화면 상태

**언제 읽나:** 데이터를 불러오거나 저장하는 화면, 폼·입력, 삭제 등 되돌리기 어려운 행동, 가입·온보딩을 설계할 때.
**연구 데모:** 1절(피드백)과 2절의 로딩·오류만 하면 된다.

## 1. 피드백 — 모든 행동에 반응한다
| 걸리는 시간 | 보여 줄 것 |
|---|---|
| 즉시(약 0.1초 이내) | 눌림 상태·값 변경만 |
| 약 1초 안팎 | 버튼 안 스피너 + 버튼 비활성(중복 제출 방지) |
| 수 초 이상 | 진행률이나 단계 표시, 취소 가능하면 취소 버튼 |
| 수십 초 이상·백그라운드 | 다른 일을 하게 두고 끝나면 알림 |
(시간 구분은 Nielsen의 응답 시간 한계 0.1/1/10초에 기반한 경험칙)

- 성공도 알린다: 저장됨 표시, 목록에 새 항목 강조. 단, 성공 알림은 짧게, 오류 알림은 사용자가 닫을 때까지 유지.
- 낙관적 업데이트(먼저 화면을 바꾸고 나중에 서버 확인)는 실패율이 낮고 되돌리기 쉬운 행동(좋아요, 정렬)에만. 결제·삭제·권한 변경은 서버 확인 후 반영.

## 2. 화면 상태 5종 (데이터가 있는 화면마다)
1. **빈 상태** — 세 종류를 구분한다.
   - 첫 사용: 이 화면이 무엇인지 한 줄 + 첫 행동 버튼(예: "첫 실험 추가"). 예시 데이터 불러오기를 주면 더 좋다.
   - 결과 없음(검색·필터): 조건을 보여 주고 "필터 해제" 버튼.
   - 모두 처리함(할 일 0건): 긍정적으로 끝맺기.
2. **로딩**
   - 레이아웃이 예측되면 스켈레톤(모양 유지로 화면 흔들림 방지), 예측 안 되거나 짧으면 스피너.
   - 아주 짧은 로딩(수백 ms)에 스피너를 깜빡이지 않게 약간 늦게 표시한다.
   - 다시 불러올 때는 기존 데이터를 유지한 채 작은 표시만.
3. **오류** — 무엇이 실패했는지 + 사용자가 할 수 있는 것(다시 시도, 다른 방법, 문의). 원인별로 구분: 네트워크 / 권한 없음 / 찾을 수 없음 / 서버 오류. 기술 메시지(스택, 500)는 접어서만.
4. **부분 실패** — 10개 중 2개 실패: 성공분은 반영하고 실패 항목만 표시 + 재시도.
5. **권한 없음·잠김** — 숨길지 비활성으로 보일지 결정: 사용자가 얻을 수 있는 기능이면 보이되 이유와 방법을 알려 주고, 관계없는 기능이면 숨긴다.

## 3. 오류 예방과 복구
- 예방이 먼저: 잘못된 선택지는 처음부터 고를 수 없게(날짜 선택기, 범위 제한), 형식은 입력 중 자동 정리(전화번호 하이픈).
- **되돌리기 > 확인 창.** 확인 창은 습관적으로 눌러 버린다. 삭제는 "삭제됨 · 실행 취소" 알림(수 초) + 휴지통이 기본.
- 확인 창은 되돌릴 수 없고 결과가 큰 행동에만: 제목에 결과를 쓰고("프로젝트 3개를 영구 삭제할까요?"), 버튼은 동사("영구 삭제" / "취소"). 아주 위험하면 이름 입력으로 확인.
- 입력한 내용은 절대 잃지 않는다: 오류가 나도 값 유지, 긴 폼은 임시 저장, 저장 안 하고 나가면 경고.

## 4. 폼
- 라벨은 입력칸 위에 항상 보이게. placeholder를 라벨 대신 쓰지 않는다(입력 시작하면 사라짐, 대비 낮음).
- 검증 시점: 형식 오류는 칸을 떠날 때(blur), 필수 누락은 제출 때. 입력하는 도중에 빨간 오류를 띄우지 않는다. 고친 뒤에는 즉시 오류 해제.
- 제출 시 오류가 여럿이면 상단에 요약 + 첫 오류 칸으로 포커스 이동.
- 필수/선택 중 적은 쪽을 표시한다(대부분 필수면 "선택" 표시).
- 이미 아는 정보를 다시 묻지 않는다(WCAG 2.2 3.3.7 Redundant Entry, A).
- 올바른 `type`/`inputmode`/`autocomplete`를 지정해 모바일 키보드와 자동 완성을 돕는다.

## 5. 온보딩
- 기본은 **안 하는 것**: 화면이 스스로 설명되면 투어가 필요 없다. 빈 상태가 최고의 온보딩이다.
- 필요하면 그 기능을 처음 쓸 때 맥락 안에서 한 번(툴팁 1개). 시작 시 5장짜리 슬라이드 투어는 대부분 건너뛴다.
- 가입 전에 가치를 먼저 보여 줄 수 있으면 그렇게(둘러보기 → 저장할 때 가입).
- 체크리스트형 온보딩은 단계가 실제 가치로 이어질 때만.

## 흔한 실수
- 저장 버튼을 눌렀는데 아무 반응 없음 → 사용자가 여러 번 눌러 중복 생성.
- 스피너 대신 빈 화면 → "데이터 없음"과 구분 불가.
- 오류 시 폼 초기화.
- 모든 삭제에 확인 창, 되돌리기 없음.
