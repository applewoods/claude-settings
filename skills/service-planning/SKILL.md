# 서비스 기획 매뉴얼

> **팀으로 진행:** 여러 단계이거나 검증이 중요한 일은 `team-orchestration` 스킬의 "서비스 기획" 팀 구성(scout·builder·expert·verifier)으로 나눠 맡긴다. 각 팀원은 이 매뉴얼을 따른다.

## 대상
- 연구 데모·프로토타입, 개인·사이드 프로젝트, 실제 출시 서비스, 내부 도구 모두 해당한다. 기획을 시작할 때 이 중 무엇인지 먼저 확인하고, 그에 맞게 깊이를 조절한다(데모는 가볍게, 출시 서비스는 꼼꼼하게).
- 플랫폼은 기본적으로 **반응형 모바일 웹 + 모바일 앱**이다. 설계는 폰 화면을 기준으로 한다.

## 진행 방식: 초안 먼저
1. 내가 아이디어를 주면 빈 곳을 묻기 전에 **합리적인 가정으로 초안부터** 만든다.
2. 가정한 부분은 `[가정]`으로 표시해서 내가 고치기 쉽게 한다.
3. 정말 판단이 안 서는 핵심 질문만 초안 끝에 3개 이내로 모아서 묻는다.

## 산출물 (프로젝트 `docs/` 폴더에 마크다운으로)
| 파일 | 내용 |
|---|---|
| `docs/prd.md` | 목표, 대상 사용자, 해결하려는 문제, 핵심 기능, 범위 밖 항목, 성공 지표 |
| `docs/user-stories.md` | "~로서, ~하고 싶다, 왜냐하면 ~" 형식의 유저 스토리와 주요 사용 시나리오 |
| `docs/screens.md` | 화면 목록과 화면 간 이동 흐름(Mermaid 흐름도) |
| `docs/mockups/*.html` | 주요 화면의 HTML 목업. 브라우저로 바로 열어 볼 수 있게, 모바일 폭 기준 |
| `docs/mvp.md` | MVP 범위와 우선순위(Must / Should / Later), 단계별 계획 |

- 목업은 디자인 완성도보다 **화면 구성과 흐름 확인**이 목적이다. 단일 HTML 파일로, 외부 의존성은 최소로.
- 만든 뒤에는 내장 브라우저로 목업을 열어 모바일 폭에서 확인한다.

## 기획 단계 필수 점검
- **개인정보·보안**: 어떤 개인정보를 왜 수집하는지, 최소 수집인지, 로그인·권한 구조는 어떤지.
- **성공 지표**: 무엇으로 잘 되고 있는지 판단할지(예: 주간 활성 사용자, 작업 완료율). 데모라면 "시연에서 보여줄 것"이 지표다.
- **경쟁·유사 서비스**: 웹 검색으로 비슷한 서비스 3~5개를 찾아 차이점을 정리한다. 확인한 출처를 함께 적는다.

## AI 기능이 들어갈 때
- AI가 맡는 부분과 일반 로직이 맡는 부분을 나눠 적는다.
- AI 응답이 틀리거나 느리거나 실패할 때 사용자에게 어떻게 보일지 정한다.
