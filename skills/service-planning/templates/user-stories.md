# [서비스 이름] 유저 스토리

> 양식 사용법: `docs/user-stories.md`로 복사. 연구 데모는 ★ 절만(시연 시나리오 스토리와 그 수용 기준). Must 스토리는 수용 기준 필수. 스토리 ID는 PRD 기능 ID·화면 ID와 연결한다.

## 작성 규칙
- 형식: "**[역할]**로서, **[행동]**하고 싶다, 왜냐하면 **[얻는 가치]**." 가치 부분이 "기능이 있어서"면 다시 쓴다.
- 크기: 한 스토리는 개발 며칠 안에 끝나고, 혼자서 사용자 가치를 낸다. 크면 여정 단계·규칙·데이터 종류로 쪼갠다(화면·기술 계층으로 쪼개지 않는다).
- 수용 기준은 **확인 가능한 문장**: 누가 봐도 통과/실패를 판단할 수 있어야 한다. 정상 흐름 1개 + 예외 흐름(입력 오류, 권한 없음, 네트워크 끊김, 빈 데이터)을 포함한다.
- "빠르게, 쉽게, 직관적으로" 금지 → 숫자·관찰 가능한 행동으로.
