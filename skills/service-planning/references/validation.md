# 가정 검증·실험·출시 계획

언제 읽나: 3단계(가정 지도), MVP를 정하기 전, 출시·실험 계획(`docs/mvp.md`)을 쓸 때. 연구 데모는 생략, 내부 도구는 핵심 가정 1~2개만.

## 1. 가정 뽑기
PRD 초안의 문장 하나하나를 "이게 사실이어야 이 기획이 성립한다" 형태로 바꾼다. 네 범주로 나눈다.

| 범주 | 질문 | 예 |
|---|---|---|
| 수요 | 원하는가, 지금 대안을 버릴 만큼? | "대학원생은 실험 노트 정리에 주 2시간 이상 쓴다" |
| 사용성 | 설명 없이 쓸 수 있는가? | "첫 사용자가 3분 안에 첫 기록을 만든다" |
| 실현성 | 만들 수 있는가(기술·데이터·법)? | "LLM이 실험 로그 요약을 90% 이상 정확하게 한다" |
| 사업성 | 지속 가능한가(비용·채널·수익)? | "사용자당 월 AI 비용이 500원 이하" |

## 2. 가정 지도 — 무엇부터 검증하나
- 두 축: **중요도**(틀리면 기획 전체가 무너지나) × **근거**(직접 관찰·데이터가 있나, 추측인가).
- "중요 + 근거 약함" 칸의 1~3개가 **가장 위험한 가정**이다. 이것을 먼저, 가장 싸게 검증한다.
- 흔한 실수: 검증하기 쉬운 것(UI 선호)부터 검증하고 안심한다 / 실현성만 검증하고(기술은 되네) 수요를 건너뛴다.

## 3. 검증 방법 고르기 (싼 것부터)
| 방법 | 확인하는 것 | 비용 | 주의 |
|---|---|---|---|
| 문제 인터뷰 (5~8명) | 문제·현재 행동 존재 여부 | 낮음 | 미래 의향("쓰겠다")은 묻지 않는다. 지난번에 실제로 어떻게 했는지 묻는다 |
| 데스크 리서치·데이터 | 시장 규모, 기존 행동 | 낮음 | 출처 확인. 오래된 통계 주의 |
| 가짜 문(fake door)·랜딩 페이지 | 클릭·사전 등록 의향 | 낮음 | 이메일 등록은 약한 신호. 사전 결제·대기열 공유가 더 강함. 개인정보 수집 시 동의 필요 |
| 컨시어지 / 오즈의 마법사 | 가치를 실제로 받는지 | 중간 | 사람이 뒤에서 처리. 확장성은 검증 못 함 |
| 클릭 가능한 목업 사용성 테스트 (5명 내외) | 사용성 | 중간 | 과업 성공률·막힌 지점을 본다. 좋아요 반응은 무시 |
| 기술 스파이크·평가셋 | 실현성(AI 품질 등) | 중간 | 실제 데이터와 비슷한 예시로. `ai-features.md` 참고 |
| 가상 사용자 사전 조사 | 시나리오·이탈 이유 **발견** | 낮음 | 결과는 `[가설]`. 검증 수단 아님 (`synthetic-user-research`) |

- 행동 > 말: 돈·시간·데이터를 내놓는 행동이 가장 강한 증거, "좋네요"가 가장 약하다.

## 4. 검증 계획 양식 (실험 카드)
```
가정: ...
방법: ...
지표와 성공 기준(실행 전 기록): 예) 랜딩 방문 200명 중 사전 등록 10% 이상
실패 시 결정: 예) 대상을 바꾸거나 기능 X를 빼고 재검증
기간·비용: ...
결과(실행 후): ... / 결정: ...
```
- 기준은 실행 **전에** 적는다. 결과를 보고 기준을 낮추면 검증이 아니다.
- 기준 숫자의 근거가 없으면 `[가정]`으로 적고, 왜 그 숫자인지 한 줄 남긴다.
- 표본이 작으면(수십 명) 비율 차이를 통계적으로 해석하지 않는다. 방향 신호로만 쓴다.

## 5. 출시 계획 (사이드·출시 서비스)
- 단계: 내부 테스트 → 소수 초대 베타(우선 타깃 10~50명 `[가정]`) → 공개. 단계마다 넘어가는 조건을 지표로 적는다.
- 기능 플래그·단계적 공개(일부 사용자에게 먼저)로 되돌릴 수 있게 한다. 되돌릴 방법이 없는 변경(데이터 구조, 가격 인상)은 더 신중히.
- A/B 테스트는 트래픽이 충분할 때만 의미가 있다. 초기 서비스는 대개 표본이 부족하므로 정성 관찰 + 전후 비교로 판단하고, 그 한계를 적는다.
- 앱은 스토어 심사 기간과 반려 사유(개인정보 처리방침 링크, 계정 삭제 기능, 결제 정책)를 일정에 넣는다. 정책 세부는 각 스토어 최신 가이드를 확인한다 `[확인 필요]`.
- 출시 체크: 측정 이벤트 동작 확인, 오류 모니터링, 문의 창구, 개인정보 처리방침·약관 게시, 장애 시 공지 방법.

## 6. 출시 후 판단
- 출시 2~4주 후 `docs/mvp.md`에 지표 결과와 결정(계속/수정/중단)을 적는다.
- 중단 기준에 걸렸는데 "조금만 더"를 반복하지 않는다. 계속하려면 새 가정과 새 기준을 적는다.
