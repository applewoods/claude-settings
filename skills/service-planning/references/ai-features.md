# AI 기능 기획

언제 읽나: 서비스에 LLM·생성형 AI·추천·분류 모델이 들어갈 때. 연구 데모는 1·3절만.

## 1. AI가 맡을 일인가
- 규칙·검색·템플릿으로 되는 일은 AI에 맡기지 않는다. 결정적이어야 하는 일(계산, 금액, 권한, 일정 충돌)은 일반 로직이 한다.
- AI가 맞는 일: 정해진 답이 없는 요약·분류·생성·자연어 이해, 틀려도 사용자가 쉽게 고칠 수 있는 일.
- PRD에 표로 나눈다: | 단계 | AI가 하는 일 | 일반 로직이 하는 일 | 사람이 확인하는 일 |

## 2. 틀림의 비용으로 설계를 정한다
| 틀렸을 때 피해 | 설계 |
|---|---|
| 작음(추천 문구, 초안) | 바로 보여 주고 편집·다시 생성 제공 |
| 중간(분류, 일정 정리) | 결과에 근거·출처 표시, 한 번에 되돌리기 |
| 큼(의료·법률·금융 판단, 타인에게 자동 발송, 삭제) | AI는 제안만, **사람 확인 후 실행**. 자동 실행 금지 |

## 3. 품질 기준 = 평가 예시
- 실제 입력과 비슷한 예시 20~50개(쉬운 것, 경계 사례, 악의적 입력 포함)에 기대 출력·합격 기준을 적은 평가셋을 기획 산출물로 만든다. 이게 없으면 "잘 된다"를 판단할 방법이 없다.
- 합격 기준 예: "요약에 원문에 없는 사실이 0개", "분류 정확도 90% 이상 `[가정]`". 데모 시연 시나리오도 이 평가셋에서 고른다.
- 모델·프롬프트를 바꿀 때마다 같은 평가셋으로 다시 잰다(회귀 확인).

## 4. 실패·지연 UX
- 느림: 응답 시간 목표(예: 첫 글자 2초 `[가정]`), 스트리밍 여부, 기다리는 동안 보여 줄 것, 취소 버튼.
- 실패(API 오류, 한도 초과): 사용자 입력이 사라지지 않게, 재시도, 대체 경로(수동 입력).
- 틀림: 신고·수정 버튼, 출처 표시, "AI가 생성한 결과" 표시(AI 기본법 제31조, `privacy-kr.md`).
- 거절·부적절 응답: 금지 주제·프롬프트 주입(사용자가 지시를 덮어쓰려는 입력)에 어떻게 보일지.
- 빈 상태: AI가 쓸 데이터가 아직 없는 첫 사용자에게 무엇을 보여 주나(콜드 스타트).

## 5. 비용·데이터
- 요청당 비용 = (입력+출력 토큰) × 단가, 사용자당 하루 요청 수 `[가정]`로 월 비용을 계산해 PRD에 적는다. 무료 한도·요청 제한을 기획 단계에서 정한다. 단가는 공급사 가격표에서 확인 `[확인 필요]`.
- 사용자 입력을 외부 LLM API로 보내면 위탁·국외 이전 고지 대상이 될 수 있다. 공급사의 데이터 학습 사용 정책(API는 기본 미사용인 경우가 많지만 계약·설정 확인 `[확인 필요]`)과 보관 기간을 적는다.
- 민감정보·타인 정보가 입력될 수 있는 기능은 전송 전 마스킹 또는 경고를 둔다.

## 6. 범용 AI와의 차별
"ChatGPT에 붙여 넣으면 되는 것 아닌가?"에 답하는 요소를 기능으로 명시한다: 사용자 데이터·맥락의 자동 결합, 업무 흐름 안 실행(알림·저장·공유), 검증된 출처, 반복 작업 자동화. 이 요소가 MVP의 Must에 들어가야 한다.

## 7. 흔한 실수
- "AI가 알아서" — 입력·출력·실패 시 동작을 안 정한다.
- 평가셋 없이 데모 몇 번 성공을 품질 근거로 쓴다.
- 비용을 출시 후에 계산한다.
- 모든 기능에 채팅 창을 붙인다 → 사용자는 빈 입력창 앞에서 무엇을 쳐야 할지 모른다. 버튼·추천 프롬프트로 시작점을 준다.
