# 개인정보·법규 점검 (한국)

언제 읽나: 6단계(개인정보·보안·법규), 회원가입·로그인·알림·결제·위치·AI 기능을 기획할 때, PRD의 개인정보 칸을 채울 때.

> **이 문서는 기획 단계 점검표이지 법률 자문이 아니다.** 조문은 2026-10-17에 국가법령정보센터(law.go.kr) 현행 조문으로 확인했다(개인정보 보호법 [시행 2026.9.11. 법률 제21445호], 같은 법 시행령 [시행 2026.9.11.], 정보통신망법 [시행 2026.10.2.], AI 기본법 [시행 2026.7.21. 개정본]). 법은 자주 바뀐다 — 출시 전에 law.go.kr과 개인정보보호위원회(pipc.go.kr) 안내서로 다시 확인하고, 출시 서비스는 전문가 검토를 받는다. 직접 확인 못 한 내용은 `[확인 필요]`.

## 1. 적용 범위
- 연구 데모: 판단 기준은 공개 여부가 아니라 **식별 가능성**이다. 직접 만든 합성·가짜 데이터만 쓰면 대부분 생략 가능. 공개 데이터셋이라도 이름·얼굴·음성·자유 텍스트 등 개인을 알아볼 수 있는 정보가 있으면 적용 대상으로 보고, 데이터셋 라이선스·이용 조건·원래 수집 목적과 우리 목적이 맞는지 확인한다 `[확인 필요]`. 사람 대상 연구면 IRB 승인 범위도 확인(기관 규정).
- 내부 도구: 직원 개인정보도 개인정보다. 접근 권한·로그가 핵심.
- 사이드·출시 서비스: 아래 전부.

## 2. 수집 항목표 (PRD에 그대로)
| 항목 | 목적 | 법적 근거 | 필수/선택 | 보관 기간 | 접근자·위탁·제공처 |
|---|---|---|---|---|---|
| 이메일 | 로그인, 공지 | 계약 이행(제15조①4) | 필수 | 탈퇴 시 파기 | 우리, 이메일 발송 업체(위탁) |
| 프로필 사진 | 프로필 표시 | 동의(제15조①1) | 선택 | 탈퇴 시 | 우리 |

판단 기준
- **목적에 연결되지 않는 항목은 뺀다.** 최소 수집이라는 입증책임은 처리자에게 있다(제16조①). "나중에 분석에 쓸지도"는 목적이 아니다.
- **법적 근거를 동의로만 생각하지 않는다.** 서비스 제공에 필요한 정보는 계약 이행(제15조①4)이 근거가 될 수 있고, 이 경우 동의 없이 처리하는 항목과 근거를 처리방침 등으로 구분해 알려야 한다(제22조③). 근거 판단이 애매하면 `[확인 필요]`.
- **선택 항목 미동의로 서비스를 거부하지 않는다**(제16조③, 제22조⑤). "전체 동의" 하나로 필수·선택·마케팅을 묶지 않는다 — 동의 사항은 구분해 각각 받는다(제22조①).
- 동의를 받을 때 알릴 것: 목적, 항목, 보유·이용 기간, 거부할 권리와 불이익(제15조②).

## 3. 플래그 — 하나라도 있으면 PRD "법규 검토 필요"에 올린다
| 플래그 | 핵심 요구 (조문) | 기획 결정 |
|---|---|---|
| **만 14세 미만 이용 가능** | 동의가 필요하면 법정대리인 동의 + 동의 확인(개인정보 보호법 제22조의2) | 연령 확인 절차를 둘지, 14세 미만을 받지 않을지 정한다. 교육·게임·가족 서비스는 거의 해당 |
| **민감정보**(건강, 사상·신념, 정치적 견해, 성생활 등 — 범위는 제23조·시행령) | 다른 동의와 **별도 동의** 또는 법령 근거, 안전조치(제23조) | 건강·멘탈·식단·수면 앱은 대부분 해당. 꼭 필요한지 먼저 묻는다 |
| **고유식별정보·주민등록번호** | 별도 동의 또는 법령 근거(제24조). 주민등록번호는 법령 근거 등 예외 외 처리 금지(제24조의2) | 본인 확인은 휴대폰·간편 인증 등 외부 수단으로. 주민번호 입력란을 만들지 않는다 |
| **외부 업체에 처리 맡김**(클라우드, 이메일·문자 발송, 분석 도구, LLM API) | 위탁 문서 + 수탁자 공개(제26조), 재위탁은 위탁자 동의 | 처리방침의 위탁 목록에 올린다 |
| **해외로 전송·보관**(해외 리전 클라우드, 해외 LLM API) | 국외 이전은 별도 동의, 또는 계약 이행에 필요한 처리위탁·보관으로서 이전 항목·국가·받는 자 등을 처리방침에 공개하거나 알리는 경우 등(제28조의8) | LLM에 사용자 입력을 보내면 해당 가능성이 크다. 어떤 데이터가 어느 나라 어느 회사로 가는지 표로 적는다 |
| **제3자에게 제공**(제휴사, 다른 서비스) | 동의 등 근거(제17조), 구분 동의(제22조①) | 위탁(우리 일을 맡김)과 제공(그들 목적으로 줌)을 구분한다 |
| **광고성 알림·문자·이메일·푸시** | 명시적 사전 동의, 오후 9시~다음 날 오전 8시는 별도 동의, 수신 거부 방법 표시, 정기적 수신동의 확인(정보통신망법 제50조; 확인 주기는 시행령 `[확인 필요]`) | 공지(서비스 필수)와 광고를 구분한다. 홍보·판매 권유용 개인정보 처리 동의도 구분해 받는다(개인정보 보호법 제22조①7) |
| **앱 접근권한**(카메라, 사진, 연락처, 위치, 마이크) | 필수/선택 구분해 항목·이유 고지 후 동의, 선택 권한 거부로 서비스 거부 금지(정보통신망법 제22조의2) | 권한은 **쓰는 순간에** 이유와 함께 요청한다. 첫 실행에 몰아서 묻지 않는다 |
| **위치정보** | 위치정보법상 사업 신고·동의 등 별도 규율 `[확인 필요]` | 정밀 위치가 정말 필요한지, 시·구 단위로 충분한지 먼저 판단 |
| **AI·자동화된 결정이 권리·의무에 중대한 영향**(채용, 대출, 자격 심사 등) | 거부·설명 요구권, 기준·절차 공개(개인정보 보호법 제37조의2; 2026.9 개정분은 2027.3.9 시행으로 표시됨 `[확인 필요]`) | 사람 검토 경로와 설명 화면을 기획에 넣는다 |

## 4. 출시 전 최소 준비물
- **개인정보 처리방침** 공개(제30조): 수집 항목·목적·보유 기간·위탁·국외 이전·파기·권리 행사 방법 등. 실제 처리와 다르면 안 된다 — 기획 단계 항목표가 원본이다.
- **안전조치**(제29조, 「개인정보의 안전성 확보조치 기준」 고시): 접근 권한 최소화, 접근 기록, 암호화(비밀번호 등), 관리자 화면 보호. 세부는 `backend`·`database` 스킬로.
- **권리 행사 경로**: 열람·정정·삭제·처리정지 요구 방법. 수집 방법보다 어렵지 않게(제38조④). 앱은 **계정 삭제** 경로를 앱 안에 둔다(스토어 정책도 요구 `[확인 필요]`).
- **파기**: 보유 기간이 끝나거나 목적을 다하면 파기(제21조). 탈퇴 후 백업·로그에 남는 데이터 처리도 정한다. (구 "1년 미이용자 파기" 유효기간제는 2023 개정으로 삭제됐다 — 2차 출처 확인, `[확인 필요]`)
- **유출 대응**: 유출을 알게 되면 원칙적으로 72시간 이내 정보주체 통지(시행령 제39조), 1천명 이상·민감/고유식별정보·외부 불법 접근에 의한 유출은 72시간 이내 개인정보보호위원회 또는 한국인터넷진흥원 신고(시행령 제40조). 2026.9.11 시행 개정으로 **유출 가능성(의심) 단계 통지**도 신설됐다(법 제34조②, 시행령 제39조의2). 기획에는 "누가 판단하고 어떻게 알리나" 담당과 연락 경로를 적는다.

## 5. 위반 시 무게 (우선순위 판단용)
- 과징금: 동의 없는 수집, 14세 미만 법정대리인 동의 위반, 민감정보·고유식별정보 위반, 위법한 국외 이전, 안전조치 미흡에 따른 유출 등에 **전체 매출액 3% 이하**, 반복·고의/중과실로 1천만명 이상 피해 등 가중 사유에는 **10% 이하**(제64조의2, 2026.3.10 개정). 관련 없는 매출은 제외하고 산정.
- 작은 서비스라도 "몰랐다"는 통하지 않는다. 기획 단계의 수집 최소화가 가장 싼 대응이다.

## 6. 흔한 실수
- 회원가입에 생년월일·성별·주소를 "기본이라서" 받는다 → 목적이 없으면 뺀다.
- 사용자 입력 원문을 LLM API와 분석 도구로 그대로 보낸다 → 위탁·국외 이전 고지 누락, 민감정보 포함 위험. 마스킹·최소 전송을 기획에 넣는다.
- 측정 이벤트 속성에 이메일·이름·자유 입력 텍스트를 넣는다.
- 공지 푸시와 광고 푸시를 구분하지 않는다.
- 처리방침을 다른 서비스에서 복사한다 → 실제 처리와 달라 그 자체가 문제.
- 데모용으로 모은 실제 데이터를 출시 서비스에 그대로 옮긴다 → 수집 목적이 다르다.
