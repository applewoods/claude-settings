# API 설계

> 언제 읽나: 새 엔드포인트를 설계할 때, 응답·에러 형식을 정할 때, 목록 API·결제·생성 요청처럼 중복 실행이 위험한 API를 만들 때.
> 적용 범위 표시: **[모두]** 데모부터 지킬 것, **[출시]** 외부 사용자가 쓰는 서비스일 때.

## 1. 먼저 정할 것: 누가 이 API를 부르나
| 호출자 | 판단 |
|---|---|
| 같은 저장소의 내 프론트엔드만 | 버전 번호 없이 시작. 대신 **호환 깨는 변경 금지 규칙**(아래 4절)을 지킨다. Next.js라면 Server Actions로 충분한 경우가 많다. |
| 모바일 앱 | 구버전 앱이 몇 달씩 살아 있다. 처음부터 `/v1` 경로 버전을 둔다. |
| 외부 개발자·다른 팀 | `/v1` + OpenAPI 문서 + 변경 공지·폐기 기간을 정한다. **[출시]** |

흔한 실수: 내부용 API에 처음부터 버전·HATEOAS·복잡한 규약을 얹는 것. 호출자가 하나면 같이 고치면 된다.

## 2. 리소스와 메서드 [모두]
- 경로는 명사 복수형(`/projects/{id}/runs`), 동사는 메서드로. 행위가 CRUD로 안 맞으면 하위 리소스(`POST /runs/{id}/cancel`)를 쓴다. 억지로 REST에 끼워 맞추지 않는다.
- `GET`은 부작용이 없어야 한다(프리페치·크롤러·재시도가 막 부른다).
- `PUT`은 전체 교체, `PATCH`는 일부 수정. PATCH에서 "필드 없음"과 "null로 지우기"를 구분한다(Pydantic `model_dump(exclude_unset=True)`).
- 상태 코드: `200` 조회·수정, `201` 생성(+`Location`), `202` 접수만 하고 나중에 처리(장시간 작업), `204` 본문 없음, `400` 형식 오류, `401` 인증 없음, `403` 권한 없음, `404` 없음(**남의 리소스도 404**로 숨길지 결정), `409` 상태 충돌, `422` 검증 실패(FastAPI 기본), `429` 레이트 리밋, `5xx`는 서버 잘못일 때만.
- 시간은 ISO 8601 + UTC(`2026-10-17T03:00:00Z`)로 주고받고, 표시용 시간대 변환은 화면에서 한다.
- 금액은 부동소수점 금지: 정수(최소 단위) 또는 decimal 문자열.
- ID: 외부에 노출하는 ID는 UUID(v7이면 정렬도 됨)나 랜덤 문자열을 검토한다. 순차 ID 자체가 취약점은 아니지만, 추측 가능하면 권한 검사 누락(BOLA)이 바로 터진다. **ID를 숨기는 것은 권한 검사의 대체가 아니다.**

## 3. 에러 응답 형식 [모두]
에러 본문 형식을 하나로 통일한다. 표준은 RFC 9457 Problem Details(`application/problem+json`, RFC 7807을 대체).
```json
{ "type": "https://example.com/errors/quota-exceeded", "title": "Quota exceeded",
  "status": 429, "detail": "월 사용량 1000건을 넘었습니다.", "code": "QUOTA_EXCEEDED",
  "request_id": "01J..." }
```
- 프론트가 분기할 값은 사람이 읽는 `detail`이 아니라 기계용 `code`로 준다.
- 검증 실패는 필드별 목록(`errors: [{field, message}]`)을 포함한다.
- `request_id`를 넣어 사용자 문의 ↔ 로그를 바로 잇는다(`observability.md`).
- **5xx 본문에 스택트레이스·SQL·내부 경로를 넣지 않는다.** 운영에서 FastAPI `debug=False`, 예외 핸들러로 일반 메시지만 반환하고 상세는 로그로.

## 4. 호환성: 깨지는 변경과 안 깨지는 변경 [모두]
- 안 깨짐(자유롭게): 응답 필드 추가, 선택 입력 필드 추가, 새 엔드포인트.
- 깨짐(버전 올리거나 단계적 전환): 필드 삭제·이름 변경·타입 변경, 필수 입력 추가, 에러 코드 의미 변경, 기본값 변경.
- 클라이언트는 모르는 필드를 무시하도록 만든다(Pydantic 응답 모델, Zod `.passthrough()` 대신 기본 strip 동작 확인).
- 단계적 전환: 새 필드 추가 → 클라이언트 이전 → 옛 필드 제거. DB 쪽 확장·축소(expand/contract) 마이그레이션은 `database` 스킬을 따른다.

## 5. 목록 API와 페이지네이션 [모두]
- 목록 API는 처음부터 **상한이 있는 페이지네이션**을 둔다. 기본 20~50, 최대 100 정도. 상한 없는 `limit`은 OWASP API4(자원 소비 무제한) 그 자체다.
| 방식 | 언제 | 주의 |
|---|---|---|
| offset/limit | 관리자 화면, 페이지 번호가 필요, 데이터가 수만 건 이하 | 깊은 페이지일수록 느려지고, 중간 삽입 시 항목이 중복·누락된다 |
| cursor(keyset) | 무한 스크롤, 피드, 많이 쌓이는 로그·메시지 | 정렬 키가 유일해야 한다(`created_at, id` 묶음). 커서는 불투명 문자열(base64)로 준다 |
- 전체 개수(`total`)는 큰 테이블에서 비싸다. 꼭 필요할 때만 주거나 추정치로.
- 필터·정렬 파라미터는 허용 목록으로만 받는다(임의 컬럼 정렬을 SQL에 그대로 넣지 않는다).

## 6. 멱등성: 같은 요청이 두 번 와도 안전하게
네트워크 타임아웃 뒤 클라이언트·프록시·사용자는 **반드시 재시도한다**. 두 번 실행되면 안 되는 POST(결제, 주문, 이메일 발송, 비싼 LLM 작업 생성)에는 멱등 키를 둔다. **[출시]**, 결제·과금이면 **[모두]**.
- 클라이언트가 `Idempotency-Key: <UUID>` 헤더를 보낸다(IETF 초안 표준화 진행 중 [확인 필요: 최신 상태]).
- 서버는 (사용자, 키)를 유니크 제약으로 저장하고, 처리 결과(상태 코드·본문)를 함께 저장한다. 같은 키 재요청 → 저장된 응답 반환. 같은 키인데 본문이 다르면 `422`/`409`.
- 처리 중 재요청이 오면 `409`로 "처리 중"을 알린다. 키 보관 기간은 24시간 정도가 흔하다(Stripe 방식).
- 단순한 대안: 자연 키에 유니크 제약(예: `(user_id, client_request_id)`), "이미 있으면 기존 것 반환".
- 서버→외부 호출 재시도도 같은 원리: 상대 API가 멱등 키를 지원하면 반드시 넘긴다(`architecture.md`).

## 7. 오래 걸리는 작업 [모두]
- 응답이 수 초를 넘을 수 있으면(LLM 일괄 처리, 파일 변환, 모델 추론) 동기 응답으로 버티지 않는다. 리버스 프록시·브라우저·로드밸런서 타임아웃이 먼저 끊는다.
- 패턴: `POST /jobs` → `202 {job_id}` → `GET /jobs/{id}`로 상태 조회(또는 SSE/웹훅 알림). 큐 선택은 `architecture.md`.
- 사용자에게 진행 상황을 보여 줘야 하는 LLM 응답은 스트리밍(`ai-features.md`).

## 8. 입력 검증 [모두]
- 경계에서 스키마로 검증: FastAPI는 Pydantic 모델, Next.js는 Zod. 타입만이 아니라 **길이·범위·개수 상한**(문자열 max_length, 배열 max_items, 숫자 범위)을 둔다. 상한 없는 입력은 메모리·LLM 비용 폭탄이 된다.
- 응답도 스키마로 내보낸다(FastAPI `response_model`). DB 모델을 그대로 반환하면 `password_hash`, `is_admin` 같은 필드가 새어 나간다(OWASP API3).
- 입력 모델에서 클라이언트가 바꾸면 안 되는 필드(`owner_id`, `role`, `price`)를 받지 않는다(mass assignment).
- Server Actions도 공개 POST 엔드포인트다. 인자를 Zod로 다시 검증하고 권한을 확인한다.

## 9. 문서 [모두]
- FastAPI: `/docs` 자동 문서를 유지하되 `summary`, 응답 예시, 에러 응답(`responses=`)을 채운다. **[출시]** 운영에서 문서를 공개할지 결정(내부 API면 `docs_url=None` 또는 인증 뒤로).
- Next.js: `docs/api.md`에 엔드포인트·입출력·에러 코드를 적는다. 외부 공개 API면 OpenAPI 생성(zod-to-openapi 등)을 검토.
- 문서와 실제가 어긋나는지는 계약 테스트로 잡는다(`testing.md`).
