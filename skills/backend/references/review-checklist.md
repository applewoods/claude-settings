# 백엔드 리뷰 체크리스트

> 언제 읽나: 백엔드 PR·코드를 리뷰할 때, `verifier`가 개발 결과를 검사할 때, 배포 전 최종 점검.
> 표시: 무표시 = 모든 단계, **[출시]** = 외부 사용자가 쓰는 서비스일 때만. 항목마다 "확인함 / 해당 없음 / 문제(위치)"로 답한다. 확인 못 한 항목은 통과로 치지 않는다.

## 1. 보안·권한 (하나라도 문제면 머지 금지)
- [ ] 새·수정 엔드포인트(Server Action 포함)마다 인증 확인이 있다.
- [ ] 리소스를 ID로 조회·수정·삭제하는 곳마다 소유자·조직 조건이 **쿼리에** 있다(BOLA).
- [ ] 관리자·역할 제한 기능에 역할 검사가 있다. Next.js는 proxy(middleware)에만 의존하지 않는다.
- [ ] 입력 스키마에 타입·길이·개수·범위 상한이 있고, 클라이언트가 바꾸면 안 되는 필드(`owner_id`, `role`, 가격)를 받지 않는다.
- [ ] 응답 스키마가 지정돼 내부 필드(해시, 토큰, 내부 플래그)가 나가지 않는다.
- [ ] SQL은 ORM·파라미터 바인딩만. 문자열 조합 SQL, `shell=True` + 사용자 입력이 없다.
- [ ] 코드·커밋·로그·에러 응답에 비밀값·개인정보가 없다. 새 환경변수는 `.env.example`에 키만 추가됐다.
- [ ] 사용자가 준 URL을 서버가 가져오면 SSRF 방어가 있다.
- [ ] 파일 업로드는 크기·형식(내용 기준) 제한과 랜덤 파일명이 있다.
- [ ] CORS는 정확한 출처 목록이고, 쿠키 인증의 상태 변경 요청은 CSRF 대책(SameSite + Origin 검사/토큰)이 있다.
- [ ] 로그인·재설정·비싼 작업에 레이트 리밋이 있다. **[출시]** 일반 API에도.

## 2. 정확성·안정성
- [ ] 여러 쓰기가 함께 성공해야 하는 곳은 하나의 트랜잭션이다.
- [ ] 동시에 두 요청이 와도 안전하다(재고·잔액·중복 생성: 유니크 제약, 조건부 업데이트, 행 잠금 중 하나).
- [ ] 결제·과금 요청에 멱등성 대책이 있다. **[출시]** 재시도될 수 있는 생성·발송 요청 전부.
- [ ] 모든 외부 호출(HTTP, LLM, 메일)에 명시적 타임아웃이 있다. 재시도는 재시도 가능한 오류에만, 한 계층에서만, 백오프+지터로.
- [ ] `async def` 안에 블로킹 호출(`requests`, 동기 DB, `time.sleep`, 무거운 CPU 작업)이 없다.
- [ ] 수 초 이상 걸리는 작업은 요청 밖(큐)으로 뺐고(예외: 사람이 보는 LLM 생성은 SSE 스트리밍 허용), 유실되면 안 되는 작업을 `BackgroundTasks`/`after()`에 두지 않았다.
- [ ] 큐 작업이 두 번 실행돼도 결과가 같다.
- [ ] 목록 API에 페이지네이션 상한이 있고, N+1 쿼리가 없다(쿼리 로그로 확인. 세부는 `database` 스킬).
- [ ] 에러 응답이 프로젝트 공통 형식이고, 5xx에 내부 정보가 없다.
- [ ] 예외를 삼키지 않는다(`except: pass` 없음). 잡으면 기록하거나 의미 있는 에러로 바꾼다.

## 3. API 계약
- [ ] 기존 클라이언트를 깨는 변경(필드 삭제·이름·타입 변경, 필수 입력 추가)이 없거나, 단계적 전환 계획이 있다.
- [ ] 상태 코드가 의미에 맞다(검증 실패 4xx, 권한 403/404, 장시간 작업 202).
- [ ] API 문서(FastAPI `/docs`의 요약·예시·에러 응답, 또는 `docs/api.md`)가 갱신됐다.

## 4. 테스트
- [ ] 새 핵심 API마다 정상 / 잘못된 입력 / 인증 없음 / **남의 리소스** / 권한 없는 역할 테스트가 있다.
- [ ] 통합 테스트가 실제 PostgreSQL로 돈다(SQLite·목 아님).
- [ ] 외부 API·LLM은 가짜 응답으로 테스트하고, 실패(타임아웃·429·깨진 응답) 경우도 있다.
- [ ] 테스트를 **실제로 실행한 출력**으로 통과를 확인했다.

## 5. 운영 준비
- [ ] 새 기능의 요청·작업이 `request_id`가 붙은 구조화 로그로 남는다. 비밀값·개인정보는 마스킹된다.
- [ ] 새 설정값이 시작 시 검증된다(없으면 바로 실패).
- [ ] DB 마이그레이션이 옛 코드와 호환되고 배포 절차에서 별도 단계로 실행된다(`database` 스킬).
- [ ] Docker 이미지: 비루트 실행, 태그 고정, `.dockerignore`에 `.env*`, 비밀값 미포함.
- [ ] Compose: DB·내부 서비스 포트 미공개, 헬스체크·`restart`·로그 회전 설정.
- [ ] `docker compose up`으로 실제로 떠서 헬스체크가 통과했다(배포 구성을 바꾼 경우).
- [ ] **[출시]** 롤백 방법(이전 이미지 태그)이 있고, 백업이 서버 밖에 있으며 복구 테스트 기록이 있다.
- [ ] **[출시]** 에러 추적·외부 업타임 감시·핵심 알림이 연결돼 있다.

## 6. LLM 기능이 있으면
- [ ] API 키가 서버에만 있고, 모델 ID가 설정값이다.
- [ ] 입력 길이·`max_tokens` 상한이 있다. 내부 단계부터는 사용자별 한도도.
- [ ] 호출마다 모델·토큰·지연·비용·프롬프트 버전이 기록된다.
- [ ] 스트리밍이면 클라이언트 연결 끊김 시 공급자 호출을 취소하고, 스트림 중 에러 이벤트가 정의돼 있다.
- [ ] LLM 출력을 검증 없이 렌더·실행·권한 판단에 쓰지 않는다. 도구 실행 권한은 서버가 현재 사용자 기준으로 검사한다.
- [ ] 프롬프트·모델 변경은 평가 세트로 이전 버전과 비교했다.

## 7. 유지보수성 (권고, 머지 차단 아님)
- [ ] 같은 업무 규칙이 두 곳 이상에 복사돼 있지 않다.
- [ ] 라우터는 HTTP 처리만, 업무 규칙은 서비스·데이터 접근 함수에 있다(규모가 커진 경우).
- [ ] 린트·타입 검사(ruff, mypy/pyright, `tsc --noEmit`)가 통과한다.
