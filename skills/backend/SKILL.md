# 백엔드 매뉴얼

> **팀으로 진행:** 여러 단계이거나 검증이 중요한 일은 `team-orchestration` 스킬의 "개발" 팀 구성(scout·builder·expert·verifier)으로 나눠 맡긴다. 각 팀원은 이 매뉴얼을 따른다.

DB 스키마·마이그레이션·쿼리·백업 세부는 `database` 스킬, 화면은 `frontend` 스킬 소관이다. 여기서는 참조만 한다.

## 적용 단계 먼저 정하기
같은 규칙도 단계마다 무게가 다르다. 작업 시작 때 어느 단계인지 확인하고(모르면 묻는다), 과한 규칙은 넣지 않는다.
| 단계 | 예 | 기준 |
|---|---|---|
| **데모** | 연구 데모, 논문 시연, 혼자 쓰는 도구 | 아래 "기본 규칙"만. 몇 초 배포 중단 허용 |
| **내부** | 연구실·팀이 실제로 쓰는 도구 | + 에러 추적, 외부 업타임 감시, 백업, LLM 비용 한도 |
| **출시** | 외부 사용자가 가입해 쓰는 서비스 | + references의 **[출시]** 항목 전부(무중단 배포, 알림, 멱등성, 보안 헤더 등) |

## 핵심 원칙
1. **권한 검사는 쿼리에 넣는다.** 가장 흔한 API 사고는 남의 데이터가 ID만 바꾸면 보이는 것(BOLA)이다. `WHERE id=:id AND owner_id=:me`.
2. **모든 외부 호출에 타임아웃, 재시도는 한 계층에서만.** 타임아웃 없는 호출 하나가 서비스 전체를 멈춘다.
3. **요청은 짧게, 긴 일은 큐로.** 수 초를 넘는 작업은 `202` + 작업 상태 조회. 유실되면 안 되는 작업은 프로세스 내 백그라운드에 두지 않는다.
4. **재시도된다고 가정한다.** 생성·결제·발송은 두 번 와도 안전하게(멱등 키·유니크 제약).
5. **경계에서 검증, 출력도 스키마로.** 입력은 상한까지 검증, 응답은 응답 모델로만 내보낸다.
6. **실제 DB로 통합 테스트.** SQLite·목으로 통과한 테스트는 운영을 보장하지 않는다.
7. **로그는 구조화, 비밀은 절대 안 찍는다.** `request_id` 하나로 요청→로그→워커를 잇는다.
8. **단순하게 시작하고 신호가 오면 키운다.** 마이크로서비스·쿠버네티스·서킷 브레이커는 필요가 확인될 때.

## 스택 선택: 상황에 따라 추천
프로젝트를 시작할 때 아래 기준으로 추천하고, 이유를 한두 줄로 설명한 뒤 확정한다.
- **화면 중심·단순 CRUD** → Next.js 서버 기능(Route Handlers / Server Actions). FE와 한 프로젝트로 관리.
- **AI 모델·데이터 처리·Python 코드가 많음** → FastAPI(Python). FE(Next.js)와 분리.
- 둘 다 해당하면: Next.js가 화면과 일반 API를, FastAPI가 AI·무거운 처리를 맡는 구성을 검토한다. 같은 도메인에서 경로로 나누면 CORS·쿠키 문제가 사라진다(`references/architecture.md` 6절).

## 인증: 상황에 따라 추천
- 직접 구현하지 않는다. 검증된 라이브러리를 쓴다.
  - Next.js 중심 → Auth.js (2025-09부터 Better Auth 팀이 유지보수, 신규 프로젝트엔 Better Auth를 권장한다는 공지가 있다. 출시 서비스를 새로 시작할 땐 이 사실을 알리고 선택을 묻는다)
  - FastAPI 중심 → FastAPI용 인증 라이브러리, 또는 표준 OAuth2/JWT 방식(공식 튜토리얼: PyJWT + pwdlib/Argon2)
- 비밀번호를 직접 저장해야 하면 Argon2id(우선)·bcrypt로 해시한다.
- 브라우저 웹앱은 HttpOnly 쿠키 세션, 모바일은 짧은 액세스 토큰 + 회전하는 리프레시 토큰. 브라우저 `localStorage`에 토큰을 두지 않는다.
- 자체 서버 배포가 기본이라 외부 인증 서비스를 쓸지는 비용·운영 부담을 비교해 제안한다.

## 기본 규칙 (모든 단계)
- **비밀값은 `.env`로.** API 키·DB 비밀번호·토큰을 코드에 넣지 않는다. `.env`는 `.gitignore`·`.dockerignore`에 넣고, 필요한 키 목록은 `.env.example`에 값 없이 적는다. 한 번 푸시된 키는 유출로 보고 교체한다.
- **입력 검증·권한 확인.** 모든 API(Server Action 포함)에서 입력을 스키마(FastAPI는 Pydantic, TS는 Zod)로 검증하고, 요청한 사용자가 그 데이터에 접근할 권한이 있는지 확인한다.
- **테스트 작성.** 핵심 API는 테스트와 함께 만든다(FastAPI: pytest, TS: Vitest). 권한 없는 접근이 막히는지도 테스트한다.
- **API 문서.** FastAPI는 자동 OpenAPI 문서(`/docs`)를 유지한다. Next.js는 `docs/api.md`에 엔드포인트·입출력을 정리한다.
- **운영 배포·운영 설정 변경 전에는 반드시 사용자에게 확인받는다.** 무엇이 바뀌는지 먼저 보여 준다.

## 배포: 자체 서버 + Docker
- `Dockerfile`과 `docker-compose.yml`로 앱·DB·리버스 프록시를 함께 띄운다. 이미지는 비루트 실행·태그 고정·git SHA 태그.
- HTTPS는 리버스 프록시(기본 Caddy, 필요 시 Nginx)로 처리한다. **DB 포트는 외부에 열지 않는다**(Docker 포트는 ufw를 우회한다).
- DB 데이터는 볼륨으로 유지하고, 백업은 서버 밖에도 둔다(세부는 `database` 스킬).
- 세부: `references/deployment.md`.

## 작업 절차
1. **파악**: 단계(데모/내부/출시), 호출자(내 FE만/모바일/외부), 스택, 기존 코드 규칙을 확인한다. 기존 프로젝트면 그 규칙을 이 매뉴얼보다 우선한다.
2. **계약 먼저**: 엔드포인트·입출력 스키마·에러 코드·권한(누가 무엇을)을 정한다. 인증·권한 구조, 분리 구성, 큐 도입 같은 되돌리기 비싼 결정은 `expert`에게 검토받는다.
3. **구현**: 스키마 → 권한 → 로직 → 외부 호출(타임아웃·재시도) 순. 해당 references를 읽고 따른다.
4. **테스트**: 정상 / 잘못된 입력 / 인증 없음 / 남의 리소스 / 권한 없는 역할. 실제로 실행해 출력으로 확인한다.
5. **운영 준비**: 로그·헬스체크·설정 검증, 필요 시 Compose로 실제 기동 확인.
6. **검증**: `references/review-checklist.md`로 자체 점검 → `verifier`(Codex) 독립 검증.
7. **배포**: 사용자 확인 후. 롤백 방법을 먼저 확인한다.

## 결정 기준표
| 질문 | 이럴 때 A | 이럴 때 B |
|---|---|---|
| 동기 vs 큐 | 1~2초 내 끝, 결과 즉시 필요 → 요청 안에서 | 수 초 이상·유실 금지·재시도 필요 → 큐 + 워커 컨테이너 |
| 프로세스 내 백그라운드 vs 큐 | 유실돼도 무방(통계·캐시) → `BackgroundTasks`/`after()` | 유실 금지 → 큐(Redis면 ARQ/RQ, 인프라 늘리기 싫으면 PostgreSQL 큐) |
| `async def` vs `def`(FastAPI) | 쓰는 라이브러리가 전부 async → `async def` | 동기 라이브러리 하나라도 → `def`(스레드풀) |
| 세션 쿠키 vs 토큰 | 브라우저 웹앱 → HttpOnly 쿠키 | 모바일·서버 간 → 짧은 토큰(+회전 리프레시) |
| offset vs cursor | 관리자 화면·페이지 번호·수만 건 이하 → offset | 무한 스크롤·계속 쌓이는 데이터 → cursor |
| API 버전 | 내 FE만 호출 → 버전 없이, 호환 깨는 변경 금지 | 모바일·외부 → `/v1`부터 |
| 재시도 | 연결 실패·타임아웃·429·502/503/504 → 백오프+지터로 2~3회 | 400/401/403/404/422 → 재시도 안 함 |
| 서킷 브레이커 | 데모·내부 → 불필요(타임아웃+제한 재시도) | 출시 + 외부 의존이 핵심 경로 → 도입 |
| 무중단 배포 | 데모·내부 → 몇 초 중단 허용 | 출시 → 블루-그린 + 확장/축소 마이그레이션 |
| LLM 응답 방식 | 사람이 보는 생성 → SSE 스트리밍 | 수십 초 이상·일괄 → 큐(+Batch API) |

## 완료 기준
- [ ] 테스트가 실제로 실행돼 통과했다(남의 리소스·권한 없는 역할 테스트 포함).
- [ ] 새 API에 입력 검증(상한 포함)과 권한 확인이 있고, 응답이 스키마로 나간다.
- [ ] 모든 외부 호출에 타임아웃이 있다.
- [ ] 코드·git·로그에 비밀값이 없다(`.env.example`만 있음).
- [ ] API 문서가 최신이다.
- [ ] `docker compose up`으로 로컬에서 실제로 떴고 헬스체크가 통과했다(배포 구성을 바꾼 경우).
- [ ] 단계에 맞는 `review-checklist.md` 항목을 확인했다(출시면 **[출시]** 항목 포함).
