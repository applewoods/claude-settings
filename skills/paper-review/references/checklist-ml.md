# 실험형 ML/DL 체크리스트
모델·기법을 제안하고 벤치마크로 보이는 논문. 해당하는 항목만 쓰고, 각 지적에 결론이 어떻게 약해지는지를 붙인다.

## 베이스라인
- 최신이고 강한 베이스라인과 비교했나, 아니면 약한 것만 골랐나.
- 베이스라인도 같은 수준으로 튜닝했나(하이퍼파라미터 탐색, 학습 예산, 데이터 증강). 제안 방법만 공들인 비교는 차이를 부풀린다.
- 숫자를 다른 논문에서 가져왔다면 설정(데이터 분할, 전처리, 평가 스크립트)이 같은가.

## 결과의 신뢰도
- 시드 여러 개, 분산·신뢰구간·유의성 검정이 있나. 개선 폭이 실행 간 편차보다 작으면 "개선"이라 하기 어렵다.
- 개선이 일부 데이터셋·지표에만 있는데 일반적인 주장을 하지 않나.
- 계산량·파라미터 수·학습 시간이 비교 대상과 비슷한가. 더 큰 모델이면 개선이 방법 덕인지 규모 덕인지 구분해야 한다.

## 원인 규명
- ablation이 각 구성 요소의 기여를 따로 보여 주나. 여러 요소를 한꺼번에 바꾸면 무엇이 효과를 냈는지 모른다.
- 제안한 설명(왜 잘 되는지)을 직접 시험했나, 아니면 결과에서 추측했나.

## 데이터와 평가
- 학습·검증·테스트 분리가 깨끗한가(테스트로 모델 선택, 데이터 중복, 사전학습 데이터 오염).
- 지표가 주장하는 능력을 실제로 재나.
- 분포가 다른 데이터·실패 사례 분석이 있나.

## 재현성 (짧게)
- 코드·체크포인트 공개, 핵심 하이퍼파라미터 명시 여부만 한 줄로 적는다.
