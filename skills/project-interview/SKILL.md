# 프로젝트 기본 인터뷰

여기서 "프로젝트"는 작업 폴더(보통 git 저장소) 단위다. 새 세션을 열었다고 새 프로젝트가 되는 것은 아니다.

## 언제 시작하나
- 작업 폴더 루트에 `CLAUDE.md`가 없고, 그 폴더에서 처음으로 실질적인 작업(파일 작성·수정, 코드 실행)을 하려 할 때.
- 다음의 경우에는 시작하지 않는다: 앱이 만든 임시 폴더("No folder" 세션), 홈 폴더나 Desktop 같은 일반 폴더, 질문 하나로 끝나는 짧은 요청.
- 사용자가 "인터뷰는 건너뛰어"라고 하면 바로 원래 요청을 처리한다. 다음에 다시 권하지 않도록, 최소한의 `CLAUDE.md`(한 줄 설명 + "인터뷰 생략")를 만들어도 되는지 묻는다.

## 진행 방법
1. 먼저 폴더 안을 훑어본다(README, 파일 구조, requirements.txt·pyproject.toml, .tex, 데이터 파일 등). 이미 알 수 있는 내용은 묻지 않고 "이렇게 파악했는데 맞나요?"로 확인만 받는다.
2. 질문은 AskUserQuestion으로 한 번에 최대 4개씩, 1~2회 안에 끝낸다. 선택지에는 폴더에서 파악한 내용을 반영한다.
3. 답변을 정리해 프로젝트 루트에 `CLAUDE.md` 초안을 쓰고, 사용자에게 보여 준 뒤 확인을 받는다.
4. 유형이 웹·앱 서비스이고 아직 기획 문서(`docs/prd.md`)가 없으면, `service-planning` 스킬로 기획 초안을 만들자고 제안한다.
5. 인터뷰가 끝나면 원래 요청으로 돌아간다.

## 물어볼 내용 (폴더에서 이미 알 수 있으면 생략)
- **유형**: 논문 / 개발 / 데이터 분석 / 문서·기획 (여러 개 선택 가능)
- **목표와 산출물**: 이 프로젝트로 무엇을 만들고, 최종 결과물은 무엇인가 (예: 학회 논문, 웹앱, 분석 보고서)
- **마감과 제출처**: 마감일, 학회·저널명, 분량·양식 제한
- **언어**: 결과물을 영어로 쓰는지 한국어로 쓰는지
- **데이터와 자료**: 데이터 위치, 형식, 민감 정보 여부, 참고 문헌 관리 방법(BibTeX, Zotero 등)
- **환경**: Python 버전, 가상환경(venv/conda/uv), 주요 라이브러리, GPU 사용 여부
- **협업**: 혼자인지 공동 작업인지, git 사용 여부
- **완료 기준**: "끝났다"를 무엇으로 판단하나 (테스트 통과, 재현 가능한 결과, 리뷰 반영 등)
- **이 프로젝트만의 규칙**: 건드리면 안 되는 파일·폴더, 지켜야 할 스타일
