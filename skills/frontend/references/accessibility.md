# 접근성

> 적용 범위: **기본 5가지(아래 1절)는 데모에도 지킨다** — 비용이 거의 없고 나중에 고치기가 비싸다. 2절 이후의 WCAG 2.2 AA 점검은 출시 서비스일 때. 공공·교육 서비스는 법적 요구가 있을 수 있다 [해당 서비스의 규정 확인 필요].

## 1. 항상 지키는 기본 5가지
1. **의미 있는 요소를 쓴다.** 클릭 동작은 `<button>`, 이동은 `<a href>`/`<Link>`. `<div onClick>`은 키보드·스크린리더에서 동작하지 않는다.
2. **모든 입력에 라벨.** `<Label htmlFor>` 또는 `aria-label`. placeholder는 라벨이 아니다(입력하면 사라진다).
3. **아이콘만 있는 버튼에 이름.** `<Button size="icon" aria-label="닫기">`. 장식 아이콘은 `aria-hidden`.
4. **포커스가 보인다.** `outline: none`만 하고 대체 스타일이 없으면 키보드 사용자가 길을 잃는다. Tailwind `focus-visible:ring-*`.
5. **색 대비.** 본문 4.5:1, 큰 글자(약 24px, 굵게 약 19px 이상)와 UI 요소 경계 3:1. 색만으로 상태를 알리지 않는다(에러는 빨간색 + 아이콘/텍스트).

## 2. 상호작용 컴포넌트
- 모달·드롭다운·콤보박스·탭·툴팁은 **shadcn/ui(Radix 기반) 것을 쓴다.** 포커스 가두기, Esc 닫기, 닫은 뒤 원래 버튼으로 포커스 복귀, 화살표 키, ARIA 속성이 이미 들어 있다. 직접 만들면 이 중 절반은 빠진다.
- shadcn `Dialog`에는 `DialogTitle`이 필요하다(시각적으로 숨기려면 `VisuallyHidden`). 빠지면 콘솔 경고가 난다.
- ARIA는 마지막 수단이다. 잘못된 `role`은 없는 것보다 나쁘다. 네이티브 요소로 안 될 때만.
- 동적 알림(저장됨, 에러 토스트)은 `aria-live` 영역으로 읽힌다(Sonner 등 토스트 라이브러리가 처리하는지 확인).
- SPA 라우트 이동 후 포커스·제목이 바뀌는지: Next.js는 라우트 이동을 알리는 기능이 있다 [확인 필요: 현재 버전의 route announcer 동작]. 페이지마다 고유한 `<title>`(metadata)과 `<h1>` 하나.

## 3. WCAG 2.2에서 새로 챙길 것(출시)
- **2.5.8 타깃 크기(최소, AA)**: 클릭 대상 24×24 CSS px 이상(또는 충분한 간격). 모바일 앱은 플랫폼 권장 44pt/48dp를 따른다.
- **2.4.11 포커스 가려짐 방지(AA)**: 고정 헤더·쿠키 배너·하단 바 아래로 포커스된 요소가 완전히 숨지 않게. `scroll-padding-top`.
- **3.3.8 접근 가능한 인증(AA)**: 로그인에서 비밀번호 붙여넣기·자동완성을 막지 않는다. 퍼즐형 인지 테스트만 강요하지 않는다.
- **2.5.7 드래그 동작(AA)**: 드래그로만 되는 기능(정렬, 슬라이더)에 클릭/버튼 대안.
- **3.3.7 중복 입력(A)**: 같은 과정에서 이미 입력한 정보를 다시 입력시키지 않는다(자동 채움 또는 선택).

## 4. 그 밖에 자주 빠지는 것
- 이미지 `alt`: 정보 이미지는 내용을, 장식은 `alt=""`. "이미지", "사진"이라고 쓰지 않는다.
- `<html lang="ko">`. 빠지면 스크린리더가 한국어를 영어 발음으로 읽는다.
- 확대: `user-scalable=no`/`maximum-scale=1` 금지. 200% 확대·320px 폭에서 가로 스크롤 없이 읽혀야 한다(1.4.10 리플로).
- 움직임: `prefers-reduced-motion`이면 큰 애니메이션·자동 재생을 줄인다(Tailwind `motion-reduce:`).
- 다크 모드에서도 대비를 다시 잰다.
- 앱(RN): `accessibilityLabel`, `accessibilityRole`, `accessibilityState`(또는 RN 최신 `aria-*`/`role` 속성 [RN 버전 확인]). 동적 글꼴 크기(Dynamic Type)를 켜도 레이아웃이 깨지지 않게 고정 높이를 피한다.

## 5. 점검 방법
| 방법 | 잡는 것 | 시간 |
|---|---|---|
| 키보드만으로 주요 흐름(Tab, Shift+Tab, Enter, Space, Esc, 화살표) | 포커스 순서·갇힘·누락 | 5분, 매 작업 |
| `eslint-plugin-jsx-a11y`(린트) | 라벨·alt·잘못된 role | 자동 |
| axe DevTools / Lighthouse 접근성, Playwright + `@axe-core/playwright` | 자동으로 찾을 수 있는 문제(대략 3~4할 수준으로 알려짐 [출처 확인 필요]) | 자동 |
| VoiceOver(macOS: Cmd+F5, iOS 시뮬레이터 Accessibility Inspector) | 읽기 순서·이름·알림 | 출시 전 핵심 화면 |

자동 도구 0건 ≠ 접근 가능. 키보드 점검은 반드시 사람이(또는 브라우저 조작으로) 한다.
