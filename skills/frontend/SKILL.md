# 프론트엔드 매뉴얼

> **팀으로 진행:** 여러 단계이거나 검증이 중요한 일은 `team-orchestration` 스킬의 "개발" 팀 구성(scout·builder·expert·verifier)으로 나눠 맡긴다. 각 팀원은 이 매뉴얼을 따른다.

## 기본 스택
- **웹**: Next.js (App Router). 템플릿 기본 설정(TypeScript)을 따른다.
- **모바일 앱**: React Native + Expo. 웹과 공유할 수 있는 로직·타입은 함께 쓴다.
- **스타일·UI**: Tailwind CSS + shadcn/ui. 모바일 앱은 NativeWind 등 Tailwind 방식에 맞는 도구를 쓴다.
- 다른 도구가 꼭 필요하면 이유를 한 줄로 설명하고 묻는다.

## 디자인
- 색·글꼴·간격은 `docs/DESIGN.md`를 따른다. 없거나 디자인을 새로 잡는 일이면 `ux-ui-design` 스킬부터 따른다.
- 랜딩·소개 페이지는 `design-taste-frontend`, 앱 화면은 이 매뉴얼과 shadcn/ui로 만든다.

## 작업 원칙
- 화면은 모바일 폭부터 만들고 넓은 화면으로 확장한다.
- shadcn/ui에 있는 컴포넌트는 새로 만들지 않고 가져다 쓴다.
- 기획 문서(`docs/`)와 목업이 있으면 그 화면 구성과 흐름을 따른다. 다르게 하고 싶으면 먼저 묻는다.
- 로딩·빈 상태·에러 상태 화면을 빠뜨리지 않는다.

## 직접 확인하고 끝낸다
- **완료라고 하기 전에 실제 화면을 띄워서 확인한다.**
  - 웹: 개발 서버를 띄우고 내장 브라우저로 열어, 모바일 폭(375px)과 데스크톱 폭에서 확인한다. 콘솔 에러도 확인한다.
  - 앱: Expo로 iOS 시뮬레이터(또는 Expo 웹)에서 띄워 확인한다.
- 확인한 화면과 확인하지 못한 부분을 보고한다.

## 완료 기준
- [ ] 바꾼 화면을 브라우저(또는 시뮬레이터)에서 직접 열어 봤다.
- [ ] 모바일 폭과 데스크톱 폭 모두에서 레이아웃이 깨지지 않는다.
- [ ] 콘솔에 새 에러가 없다.
- [ ] 로딩·빈 상태·에러 상태가 처리돼 있다.
- [ ] 배포 전이면 `web-design-guidelines`로 바꾼 화면 코드를 검사했다.
