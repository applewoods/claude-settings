# 섹션별 작성 가이드

**언제 읽나:** 섹션 초안을 쓰거나, 섹션 단위로 구조를 고칠 때. 문장 교정만 할 때는 해당 섹션 부분만 본다.
**공통 원칙:** 각 섹션은 핵심 주장 목록(C1~C3, `SKILL.md`)에 대해 맡은 역할이 다르다. 섹션을 쓰기 전에 "이 섹션을 읽은 리뷰어가 무엇을 믿게 되어야 하는가"를 한 문장으로 적는다.

## 쓰는 순서 (권장)
방법 → 결과 → 논의 → 서론 → 관련연구 → 결론 → 초록 → 제목.
이유: 서론·초록은 결과가 확정돼야 정직하게 쓸 수 있다. 서론을 먼저 쓰면 결과가 따라오지 않은 주장이 남는다. 단, 서론 **개요**(논리 흐름 6줄)는 기획 단계에서 미리 써 둔다.

## 제목
- 무엇을(과제) + 어떻게/무엇이 새로운지(핵심 아이디어)가 보이게. 결과를 넣으려면 근거가 확실한 것만.
- 피한다: 모호한 약어만으로 된 제목, "A Novel ~", "Towards ~"로 실제보다 큰 범위 암시.

## 초록 (영어 150–250단어 수준, 투고처 제한 우선)
5–6문장 구조:
1. 맥락·문제 (왜 중요한가) 2. 기존 접근의 구체적 한계 3. 우리 접근의 핵심 아이디어 (기능 나열이 아니라 원리 한 줄) 4. 실험 설정 (데이터·비교 대상) 5. 핵심 결과 (수치는 본문 표와 동일하게, 비교 기준 명시) 6. 의미·함의 (과장 없이)
- 판단 기준: 초록만 읽고 "무엇을, 왜, 어떻게, 얼마나"에 답할 수 있는가.
- 흔한 실수: 1–2번이 길고 5번이 없음 / "promising results" 같은 내용 없는 결과 / 본문에 없는 주장.

## 서론
논리 흐름 (문단 단위, 4–6문단):
1. **문제와 중요성** — 넓게 시작하되 둘째 문장 안에 우리 문제로 좁힌다.
2. **왜 어려운가** — 기술적 난점. 이게 없으면 "그냥 하면 되는 일"로 읽힌다.
3. **기존 접근과 그 한계** — 묶어서(2–3개 계열), 각 한계에 근거(인용 또는 예비 실험).
4. **우리의 핵심 통찰·접근** — 한계와 1:1로 대응되게.
5. **기여 목록** — 2–4개 bullet. 각 기여는 "무엇을 했다 + 그것이 무엇을 보였다/가능하게 했다"이고, 근거 섹션을 괄호로 붙일 수 있게.
6. (선택) 결과 요약 또는 논문 구성 한 줄. 구성 문단("Section 2 describes…")은 분량이 빠듯하면 뺀다.
- 판단 기준: 3번의 한계와 4번의 접근, 5번의 기여, 실험이 하나의 선으로 이어지는가. 서론에 제기한 한계를 실험에서 검증하지 않으면 리뷰어가 바로 지적한다.
- 흔한 실수: 기여가 기능 나열 / "No prior work has…"를 근거 없이 단정 / 3번이 관련연구 섹션과 중복되어 길어짐.

## 관련연구
- **비교 축으로 묶는다.** 논문별 요약("A et al. proposed…. B et al. proposed….")을 나열하지 않는다. 묶음마다: 이 계열의 공통 아이디어 → 대표 연구 → 공통 한계 → 우리와의 차이 한 문장.
- 가장 가까운 연구 1–3편은 차이를 구체적으로(가정, 입력, 목표, 평가 설정) 쓴다. 리뷰어는 자기 논문이나 가장 가까운 연구가 빠졌는지 먼저 본다.
- 최신성: 투고 시점 기준 최근 1년의 주요 학회·arXiv를 확인했는지 적어 둔다(확인 범위를 `docs/research-plan.md`의 선행연구 지도에 기록).
- 공정성: 경쟁 연구를 깎아내리지 않는다("fail to", "naive"). 한계는 사실로 쓴다("assume access to labeled target data").
- 위치: 서론 직후(배경 지식이 필요할 때) 또는 결론 직전(우리 방법과의 비교가 핵심일 때). 투고처 관례를 따른다.

## 방법
- 목표: **독자가 이 섹션과 부록만으로 재구현할 수 있다.**
- 구성: 문제 정의·기호 → 전체 개요(그림 1개) → 구성 요소별 설명(각각 왜 필요한지 한 줄) → 학습·추론 절차 → 복잡도·비용(해당 시).
- 기호는 처음 등장할 때 정의하고, 표기 일관성 유지(벡터 굵게, 집합 대문자 등). 정의하지 않은 기호를 쓰지 않는다.
- 설계 선택마다 "왜"를 쓴다. 이유가 실험(ablation)이면 그 위치를 연결한다.
- 흔한 실수: 구현 세부(라이브러리 호출)를 원리 설명보다 길게 씀 / 다른 논문의 기존 기법을 우리 기여처럼 서술(출처 표시 필수).

## 실험 설정
- 데이터셋(출처·버전·라이선스·분할·전처리), 비교 대상(베이스라인 선정 이유, 재현했는지 수치 인용했는지), 평가 지표(정의와 선택 이유), 구현(하이퍼파라미터·탐색 범위·탐색에 쓴 데이터, 시드 수, 하드웨어·학습 시간).
- 베이스라인을 같은 조건(데이터·튜닝 예산)으로 돌렸는지 명시. 베이스라인 수치를 원 논문에서 가져왔으면 설정 차이를 밝힌다.
- 분석 방법 자체(통계 검정 선택, 누수 점검 등)는 `data-analysis` 스킬을 따른다.

## 결과
- **관찰만 쓴다.** "Table 2 shows X outperforms Y by 3.1 points on A (mean ± std over 5 seeds; paired test p < 0.01)." 우열 표현은 차이의 검정·신뢰구간이 뒷받침할 때만. 해석("this is because…")은 논의로 보낸다. 짧은 해석이 꼭 필요하면 관찰과 문장을 분리하고 추측임을 표시("We hypothesize…").
- 순서: 핵심 주장(C1) 근거 → 나머지 주장 → ablation → 추가 분석. 각 하위절 첫 문장은 그 절이 답하는 질문.
- 모든 표·그림은 본문에서 한 번 이상 언급하고, 무엇을 봐야 하는지 말한다.
- 불리한 결과(우리 방법이 지는 데이터셋)도 보고하고 논의에서 다룬다. 숨기면 리뷰어가 찾아낸다.
- 수치: 분산(표준편차·신뢰구간), 시드 수, 검정을 같이. 소수점 자릿수는 측정 정밀도와 맞춘다.

## 논의
- 결과가 **왜** 그런지(근거 있는 설명과 추측을 구분), 언제 작동하지 않는지, 기존 연구 결과와 어떻게 맞거나 어긋나는지, 실무·연구적 함의.
- 대안 설명을 직접 다룬다: "성능 향상이 파라미터 수 증가 때문은 아닌가?" → 통제 실험 위치.

## 한계 (Limitations)
- 진짜 한계를 쓴다: 가정의 범위, 평가하지 않은 조건, 데이터 편향, 계산 비용, 일반화 범위. 각 한계가 결론의 어느 주장을 얼마나 제약하는지까지.
- "향후 연구" 나열로 한계를 대신하지 않는다. 일부 투고처는 한계 절을 필수로 요구하고 분량 제외 여부가 다르다 — 투고처 지침 확인.

## 결론
- 새 주장·새 수치를 넣지 않는다. 초록의 재진술이 아니라 "무엇을 보였고, 그래서 무엇이 달라지는가"를 3–5문장으로.

## 부록·보충 자료
- 본문 주장에 꼭 필요한 근거는 본문에 둔다. 리뷰어는 부록을 읽을 의무가 없다(투고처마다 다름).
- 부록에는 증명, 추가 ablation, 하이퍼파라미터 표, 데이터 상세, 추가 정성 예시.

## 한국어 논문에서 다른 점
- 국내 학술지는 국문 초록과 영문 초록을 모두 요구하는 경우가 많다 — 영문 초록은 국문의 직역이 아니라 위 초록 구조로 따로 다듬는다.
- 구성 관례(서론–관련연구–제안 방법–실험–결론)와 분량·서식은 학회 템플릿을 따른다. 세부 문체: `style-and-claims.md` §4.
