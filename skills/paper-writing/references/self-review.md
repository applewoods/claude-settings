# 제출 전 자가 점검 (리뷰어 체크리스트)

**언제 읽나:** 원고 전체 또는 섹션을 제출 전에 점검할 때, "리뷰어라면 뭐라고 할까"를 물을 때, Codex 검증 브리핑을 만들 때.

## 진행 방식
1. 리뷰어처럼 **처음 읽는 사람**으로 읽는다: 제목 → 초록 → 그림 1 → 서론 마지막 문단(기여) → 결과 표 → 나머지. 리뷰어 다수가 이 순서로 판단을 굳힌다.
2. 각 지적을 **심각도**로 분류해 표로 보고한다.
   - 치명: 그대로면 reject 사유 (주장–근거 불일치, 핵심 베이스라인 누락, 평가 결함, 윤리·익명화 위반)
   - 주요: 점수를 깎는 사유 (재현 정보 부족, ablation 없음, 가까운 연구와 차이 불명, 과장)
   - 사소: 표현·서식·오탈자
3. 지적마다 **위치(섹션·줄·표) + 왜 문제인가 + 고치는 방법(실험 추가/범위 축소/서술 수정)**. 실험 추가가 필요한 지적은 마감까지 가능한지 따로 표시한다.
4. 강점도 2–3개 적는다(리뷰어가 강점으로 볼 것). 논문 홍보 문장을 그 강점에 맞추는 데 쓴다.

## 체크리스트
**A. 주장과 기여**
- [ ] 기여가 2–4개로 명확하고, 기능 나열이 아니라 "무엇을 보였는가"로 쓰였다.
- [ ] 각 기여에 대응하는 실험·분석이 있다(핵심 주장 목록과 대조).
- [ ] 가장 가까운 선행연구 대비 차이가 한 문장으로 말해진다. "증분적(incremental)"이라는 평을 받을 여지가 있으면 차이의 의미를 서론에서 직접 다뤘다.
- [ ] 초록·서론·결론의 주장이 서로, 그리고 결과와 일치한다.

**B. 평가**
- [ ] 베이스라인이 최신이고 강하며, 같은 조건(데이터·튜닝 예산·계산량)으로 비교했다.
- [ ] 평가 지표가 주장에 맞다(예: 효율 주장에는 시간·메모리, 공정성 주장에는 집단별 지표).
- [ ] 분산·시드 수·통계 검정이 있다. 차이가 분산 범위 안이면 "outperforms"라고 쓰지 않았다.
- [ ] ablation이 각 구성 요소의 필요성을 보인다.
- [ ] 테스트 데이터로 하이퍼파라미터를 고르지 않았다(누수). 데이터 오염(사전학습 데이터에 테스트셋 포함) 가능성을 다뤘다(해당 시).
- [ ] 불리한 결과·실패 사례를 숨기지 않았다.

**C. 재현성**
- [ ] 데이터·분할·전처리·하이퍼파라미터·시드·하드웨어·학습 시간이 본문 또는 부록에 있다.
- [ ] 코드·데이터 공개 계획 또는 불가 사유가 있다. 투고처 체크리스트(재현성·윤리 체크리스트가 있는 경우)를 채웠다.

**D. 서술**
- [ ] 첫 문장만 읽어도 각 섹션의 논리가 보인다.
- [ ] 결과와 해석이 분리돼 있다.
- [ ] 모든 그림·표가 본문에서 언급되고 캡션이 독립적으로 읽힌다.
- [ ] 정의 안 된 기호·약어가 없다. 용어가 일관된다.
- [ ] 과장 표현이 `style-and-claims.md` §2 기준을 지킨다.

**E. 인용**
- [ ] 모든 참고문헌이 실존 확인됐다(미확인은 `[확인 필요]`, 제출 전 0개).
- [ ] 인용이 각 문장을 실제로 뒷받침한다(핵심 주장 근처 인용은 원문 대조).
- [ ] 최근 1년 관련 연구를 확인했다.

**F. 윤리·형식**
- [ ] 한계 절이 실제 한계를 다룬다.
- [ ] 인간 대상·개인정보 데이터 사용 시 IRB 승인(또는 면제 판정)과 데이터 사용 권한을 밝혔다.
- [ ] 이중 맹검(double-blind)이면 익명화: 저자명·소속·감사의 글, 자기 인용의 3인칭 처리, 코드 저장소 링크 익명화, PDF 메타데이터.
- [ ] 분량·템플릿·필수 절(limitations, ethics statement, broader impact 등)이 투고처 요건에 맞다 `[확인 필요: 투고처 CFP]`.
- [ ] 생성형 AI 사용 고지가 투고처 정책대로 들어갔다(`ai-and-integrity.md`).

## 리뷰어가 자주 쓰는 지적 (미리 막을 것)
- "The novelty is limited / incremental." → 차이와 그 의미를 서론·관련연구에서 명시, 단순 조합이 아니라는 근거(왜 그 조합이 자명하지 않은가).
- "Missing comparison with X." → 가장 가까운 연구 비교, 못 하면 이유(코드 비공개, 설정 상이)를 본문에.
- "Improvements are marginal / within variance." → 분산·검정 보고, 효과 크기의 실제 의미.
- "Experiments are limited to small/synthetic datasets." → 범위를 결론에서 정직하게 한정하거나 실험 추가.
- "Unclear how hyperparameters were chosen." → 탐색 범위와 검증 데이터 명시.
- "Claims are not supported." → 핵심 주장 목록으로 대조.

## Codex 검증과 연결
제출 전 원고 검증은 `team-orchestration`의 강화 검증(`-t paper --web`, 필요 시 `-e xhigh`)을 쓰고, 브리핑에 위 체크리스트와 핵심 주장 목록을 넣는다.
