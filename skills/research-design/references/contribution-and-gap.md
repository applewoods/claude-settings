# 연구 질문 · 선행연구 지도 · gap · 기여

**언제 읽나:** 연구 질문을 다듬을 때(§1), 선행연구를 조사·정리할 때(§2), 차별점을 주장할 때(§3), 기여 문장을 쓸 때(§4).

## §1. 연구 질문 다듬기
**넓은 주제 → 검증 가능한 RQ로 좁히는 4단계**
1. 주제: "LLM으로 임상 노트 요약"
2. 문제: 무엇이 안 되는가? "요약에 원문에 없는 내용(환각)이 섞인다"
3. 원인 가설: 왜 안 되는가? "약어·수치가 많은 노트에서 근거 구간을 놓친다"
4. RQ: "약어·수치 밀도가 높은 임상 노트에서, 근거 구간을 먼저 추출하는 2단계 요약이 단일 단계 요약보다 사실 일관성 지표(지표명)를 개선하는가?"

**판단 기준**
| 기준 | 질문 | 실패 예 |
|---|---|---|
| 반증 가능 | 어떤 결과면 "아니오"인가? | "X가 도움이 되는지 탐색한다" |
| 측정 가능 | 지표가 정해져 있나? | "더 자연스러운 응답" (측정 방법 없음) |
| 실행 가능 | 데이터·자원·기간 안에 되나? | 비공개 병원 데이터 전제, 접근 계획 없음 |
| 의미 | 답이 나오면 무엇이 바뀌나? | 이미 알려진 결과의 재확인(재현 연구로 명시하지 않은 경우) |
| 범위 | 한 논문 분량인가? | RQ 안에 독립 질문 3개 |

- RQ가 여러 개면 주 RQ 1개 + 하위 RQ 2개 이내. 하위 RQ는 주 RQ의 답을 지지하거나 설명해야 한다.
- 탐색적 연구도 가능하지만 그렇다고 밝힌다. 탐색 결과를 확증처럼 쓰지 않는다.

## §2. 선행연구 지도 (literature map)
**목적:** 우리 연구가 놓일 자리를 근거로 보이고, 리뷰어가 "X를 빠뜨렸다"고 할 여지를 없앤다.

**절차**
1. 검색 범위를 기록한다: 키워드(동의어 포함), 출처(ACL Anthology, OpenReview, DBLP, Google Scholar, arXiv, 분야 저널, 국내는 KCI·DBpia 등), 기간, 날짜.
2. 씨앗 논문 3–5편에서 앞으로(인용한 논문)·뒤로(인용된 논문) 확장한다. 가장 최근 서베이가 있으면 출발점으로 쓰되 서베이 이후 연구를 따로 찾는다.
3. 각 논문에서 **비교 축의 값**만 뽑는다(요약이 아니라 분류): 과제, 가정(지도/비지도, 데이터 접근), 방법 계열, 평가 데이터·지표, 보고된 한계.
4. 표로 배치한다.

| 연구 | 축1: 가정 | 축2: 방법 계열 | 축3: 평가 설정 | 한계(원문 근거) | 우리와 차이 |
|---|---|---|---|---|---|

5. 빈 칸·드문 조합이 gap 후보. 가장 가까운 연구 1–3편을 표시.

- 문헌은 실제로 확인한 것만 넣는다(`paper-writing`의 인용 확인 규칙). 초록만 읽은 논문은 "초록 기준"으로 표시해 깊게 확인할 대상과 구분한다.
- 최근 1년 주요 학회 proceedings와 arXiv를 따로 훑는다. AI 분야는 투고 직전에도 다시 확인한다(경쟁 연구 등장 위험).

## §3. gap 주장의 근거
**gap 유형과 필요한 근거**
| gap 유형 | 예 | 필요한 근거 |
|---|---|---|
| 설정 gap | 기존 방법은 레이블 있는 목표 데이터를 가정 | 가정을 명시한 원문 인용 2편 이상 |
| 성능·한계 gap | 기존 방법은 긴 입력에서 성능 급락 | 원 논문의 보고 결과 또는 우리 예비 실험 |
| 평가 gap | 기존 벤치마크가 X를 측정하지 못함 | 벤치마크 구성 분석, 실패 사례 |
| 이해 gap | 왜 작동하는지 설명 없음 | 상충하는 보고, 설명 없는 현상 인용 |
| 적용 gap | 특정 도메인·언어(예: 한국어)에서 검증 안 됨 | 기존 평가 범위 표 + **그 도메인이 왜 다른지**의 근거 |

**판단 기준**
- "아무도 안 했다"만으로는 gap이 아니다. **왜 해야 하는가**(중요성)와 **왜 기존 방법으로 안 되는가**(난점)가 함께 있어야 한다.
- 적용 gap(새 도메인·언어에 기존 방법 적용)은 단독으로 약한 기여로 평가되기 쉽다. 그 도메인 고유의 난점과 그에 맞춘 방법·분석이 있어야 한다.
- "to our knowledge, the first"는 §2 지도를 마친 뒤에만. 지도 범위(기간·출처)를 근거로 남긴다.

## §4. 기여 유형과 진술
| 유형 | 리뷰어가 보는 것 | 반드시 있어야 할 검증 |
|---|---|---|
| 새 방법 | 기존 대비 무엇이 새로운 원리인가, 왜 작동하는가 | 강한 베이스라인 비교, ablation, 분석 |
| 새 과제·문제 정의 | 왜 이 문제가 중요하고 기존 과제로 환원되지 않는가 | 과제 정의, 평가 프로토콜, 기존 방법의 실패 |
| 데이터셋·벤치마크 | 품질·규모·다양성, 기존 대비 새로 측정하는 것, 라이선스 | 구축 절차, 주석 일치도, 기존 모델 평가 결과, 데이터 카드 |
| 실증·평가 연구 | 결론의 일반성, 실험 설계의 엄밀성, 새로운 발견 | 다양한 모델·데이터, 통제된 비교, 통계 |
| 이론 | 가정의 현실성, 결과의 의미 | 증명, (가능하면) 실험적 확인 |
| 시스템·도구 | 실제 문제 해결, 사용성, 확장성 | 사례·사용자 평가, 성능 측정 |
| 재현·부정적 결과 | 원 주장과의 차이와 그 원인 | 원 설정 재현, 차이 분석 |

**기여 문장 쓰기**
- 형식: [무엇을 했다] + [그것이 무엇을 보였다/가능하게 했다] + [근거 위치].
- 나쁜 예: "We propose a dual-branch encoder with a gated fusion module and a contrastive loss."
- 좋은 예: "We show that separating evidence extraction from generation reduces factual errors in clinical summaries by X% without fine-tuning (Sec. 5.1)." (X는 실제 결과로만 채운다)
- 기획 단계에서는 결과 자리를 비워 두고 "[결과: Table 2에서 확인 예정]"처럼 검증 위치만 연결한다.
- 기여 2–4개. 데이터셋·코드 공개는 단독 기여로 세지 않는 학회가 많다(벤치마크 트랙 제외).

**흔한 실수**
- 기여를 모듈 목록으로 씀.
- 기여와 실험이 따로 놂(기여 3에 대응 실험 없음).
- "extensive experiments demonstrate effectiveness"를 기여로 셈.
- 기여 간 중복(같은 결과를 두 번 셈).
