# 지식 위키 운영

위키 위치는 `~/wiki`(없으면 이 컴퓨터에는 위키가 없다고 알리고 멈춘다). 페이지 양식·파일명·출처 규칙은 `~/wiki/CLAUDE.md`가 기준이며, 작업 전에 반드시 읽는다. 이 스킬은 절차만 다룬다.

## 공통
- 항상 `~/wiki/index.md`부터 읽고 관련 페이지를 고른다. 위키 전체를 훑지 않는다.
- `raw/`는 읽기만 한다.
- 작업이 끝나면 점검 스크립트를 돌리고, `log.md`에 기록하고, 커밋한다.
  ```bash
  python3 "${CLAUDE_SETTINGS_DIR:-$HOME/claude-settings}/skills/wiki/scripts/lint.py" ~/wiki
  ```
  ```bash
  git -C ~/wiki add -A && git -C ~/wiki commit -m "<작업>: <제목>"
  ```

## 1. 넣기 (ingest)
사용자가 자료를 주거나(`raw/`에 넣었다고 하거나 파일·URL·대화 내용을 줌) 정리를 요청할 때.
1. 자료가 `raw/` 밖에 있으면 `raw/`로 복사한다(원본 이동·삭제 금지). URL은 본문을 마크다운으로 저장한다(`raw/<날짜>-<제목>.md`, 맨 위에 URL과 접근일). 대화 내용은 `raw/<날짜>-note-<주제>.md`로 저장한다.
2. 자료를 읽고, 사용자에게 핵심 내용 3~5줄과 만들거나 고칠 페이지 목록을 먼저 보여 준다. 사용자가 강조할 점을 말하면 반영한다.
3. 요약 페이지를 만든다(논문이면 `wiki/papers/`).
4. 자료에 나오는 주요 개념·기법·데이터셋 페이지를 확인한다. 있으면 새 내용과 출처를 추가하고, 없고 중요하면 새로 만든다. 자료 하나로 보통 3~10개 페이지가 바뀐다.
5. 기존 페이지와 상충하는 내용은 `> [!warning] 상충` 블록으로 표시한다.
6. `index.md`를 갱신하고, 점검 → 기록 → 커밋한다.

수치·인용은 원문에서 확인한 것만 쓰고, 페이지와 표 번호를 출처에 단다. 원문 확인이 안 되면 `[확인 필요]`로 표시한다.

## 2. 찾기 (query)
위키에 있는 지식이 필요한 질문일 때.
1. `index.md`에서 관련 페이지를 골라 읽고, 필요하면 링크를 따라 1~2단계 더 읽는다.
2. 답에는 근거 페이지를 `[[페이지]]`로 단다. 위키에 없는 내용은 "위키에 없음"이라고 구분해서 말한다.
3. 여러 페이지를 엮어 만든 답, 비교표 같은 결과가 다시 쓸 만하면 새 페이지로 저장할지 묻는다. 저장하면 넣기와 같이 index·점검·기록·커밋까지 한다.

## 3. 점검 (lint)
사용자가 요청할 때, 또는 넣기를 10번쯤 한 뒤 제안한다.
1. 점검 스크립트로 기계적인 문제를 찾는다: 깨진 링크, index에 없는 페이지, 아무도 링크하지 않는 페이지, frontmatter·출처 누락.
2. 내용 점검은 직접 읽어서 한다: 페이지 사이 모순, 최신 자료로 바뀐 주장, 출처 없는 문장, 합치거나 나눌 페이지, 새로 만들 만한 개념(자주 언급되는데 페이지가 없음).
3. 결과를 목록으로 보여 주고, 고칠 항목을 사용자가 고르게 한다. 큰 변경은 diff를 보여 주고 확인을 받는다.
4. 내용 점검 결과는 verifier로 독립 검증할 수 있다. 다만 미공개 연구 자료가 있으면 외부 전송 전에 사용자에게 묻는다.

## 하지 않을 것
- `raw/` 수정·삭제, 출처 없는 내용 추가, 사용자 확인 없는 페이지 삭제, 원격 push.
